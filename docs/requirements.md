# Tracelo 产品需求

> 2026-10-16 最新界面决定：移除任务与分组的 Emoji／Noto 图标展示和选择入口，封面、展开看板及桌面任务选择器使用文字身份；操作图标和品牌标记保留。旧存档的 `icon` 字段与历史只作兼容，不批量清理或改写。此决定覆盖下文历史图标设计。

更新日期：2026-10-16 · 当前发布基线：0.9.7

本文描述当前产品规则，旧版演变集中在文末历史章节。0.9.7 的修复、升级和交付见[发布说明](releases/0.9.7.md)及[发布验收](validation/2026-10-08-release-097.md)。本轮用户确认推进日常流程验收、使用观察、长历史检索和文档统一；新增能力属于本地开发改动，不能视为已发布版本。

自动回归、真实宿主／原生冒烟、人工设备验收分别记录。实际中文候选窗、多屏、Windows 和听写等尚未完成的范围保留在[当前待办](../task.md)。

## 1. 产品目标

Tracelo 帮助频繁切换工作的人记住正在做什么、推进到哪里和下一步是什么。主画面以持续推进的任务卡片和最新进展为核心；任务跨天持续存在，不因日期切换而重复创建。待办、截止日期、详情及图片均为可选信息。

右侧下方默认显示工作对话，保留上方日期切换、整周日期和当日截止任务。每日活动与单任务完整历史保留明确入口。展开卡片不打断对话，也不隐式改变 @引用；查看历史后返回对话保留输入、引用和阅读位置。详见[工作对话](design/work-conversation.md)。

插件和独立快捷工具的顶栏只保留“新建任务／记录进展”，新建内部使用“手动填写／一句话整理”，两种草稿独立保留。快捷程序进展直接输入；Obsidian 任务菜单保留“一句话记录进展”。模型服务地址支持 HTTP／HTTPS Chat Completions 兼容接口及自建服务器端口与路径；模型设置直接输入／粘贴 API Key，默认隐藏、可显示；旧密钥文件配置仅兼容读取。模型建议经过可编辑预览和用户确认后，通过既有服务保存。

正式任务使用可编辑 YAML＋Markdown，任务身份、历史、附件及草稿受存档保护规则约束。手机和人生工作台不在本仓范围内。

## 2. 已确认：主画面与视图

2026-10-16 已确认本地开发版切换为[银灰玻璃工作台](design/task-stage.md)：默认上方展示当前任务的最新进展、待办与详情，下方为只显示身份与属性的封面流；任务存在材料目录时增加只读目录树列，不自动创建目录。封面按固定顺序单次排列，每个任务只显示一张；浏览到首尾停止，对应方向按钮禁用，不再循环或复制卡片；滚轮／左右键仅浏览，点击或回车才切换展示台，不改变对话引用。分组与象限取交集；筛选排除当前任务时保留当前任务与草稿并提示。全屏总览使用同一套封面卡网格，点卡返回展示台，支持分组／四象限；“展开看板”保留以下既有完整阅读、原位编辑和展示模式。工作助手可收起，保留日期、截止、对话及活动／单任务历史入口。以下卡片网格约束适用于展开看板，不再代表默认首页布局。

- 宽窗口左侧以任务卡片为主体，右侧常驻工作侧栏，两者同时展示、独立滚动。780px 以下提供“任务看板／工作对话”切换，历史使用同一侧栏并保留明确返回入口；切换保留草稿及各自阅读位置。
- 左侧支持“分组视图”和“四象限视图”切换，共享同一批任务。
- 分组视图按业务分组展示任务；四象限视图按重要、紧急两个独立属性展示任务。
- 分组区块上下排列；四象限区块保持 2×2 排列（容器窄于 480px 时改为单列）。区块内卡片共用横向自适应铺排规则，按各自可用宽度换行，支持顶部对齐和瀑布流。
- 四个象限为：重要且紧急、重要不紧急、紧急不重要、不重要不紧急。不再使用高、中、低单一优先级。
- 所有进行中的任务持续显示，直到正常完成或异常关闭。
- 统一“已结束”入口显示已完成与异常关闭任务；当前开发版提供列表弹窗，可重开或跳回完整任务卡片查看详情和历史。
- 右侧切换日期只影响每日时间线，左侧始终显示当前待办及最新进展。
- 顶栏第一排提供搜索、截止日历和设置，不再提供独立“快捷记录”图标。第二排包含视图、分组筛选和上下文操作；分组按排序显示前面的，放不下的收入“更多分组”，选中折叠项时入口显示该分组名。
- 顶栏操作统一使用图标加可见文字，包括“截止日历”“设置”“展示模式”“管理分组”“新建任务”；窄窗口允许工具栏换行，不隐藏操作说明。今日截止由侧边栏提示，顶部不再保留重复的“今天截止”筛选按钮。
- 五主题与深浅色覆盖看板、弹窗和卡片右键菜单；新增默认黑白灰主题“素白”，仅调整配色，保留布局。旧主题仍可选，已有保存的主题选择继续保留；主题名称为“素白、矿物绿、石墨紫、冰川蓝、暖白朱砂”，不带字母编号。快捷窗口读取同一主题配置。
- 品牌标记采用居中的黑白灰 T 形与轨迹点，顶栏和新建／记录进展窗口共用，不跟随主题色改变；缩放为 60%～120%，布局可选顶部对齐或稳定瀑布流。

## 3. 已确认：任务卡片与新建

### 3.1 卡片信息

展开看板中的卡片呈现任务名称、最新进展、业务分组、重要与紧急属性以及任务状态。无需打开详情即可了解当前进展。

### 3.2 新建

- 通过弹窗新建任务。
- 顶部新建带入当前分组筛选；“全部”或“未分组”时使用未分组。分组内新建带入该分组，象限内新建带入该象限，所有预选项均可修改。默认不重要不紧急，只填写名称即可创建。
- 创建任务时记录创建事件。
- 名称必填，业务分组可选，默认“未分组”；允许填写初始进展，填写时作为独立进展事件追加。

### 3.3 点击与提交

默认工作台点封面切换展示台，展示台内记录与编辑复用既有存档／草稿服务。展开看板中点击标题、非交互正文或空白区域，卡片在原位、原宽度展开或收起。按钮、链接、图片、文字选择、复选框和输入框不误触展开；中文组合输入期间不替换输入节点。展开不切换右侧对话、不改变 @引用。

通过“查看历史”显式进入该任务跨天完整历史；返回对话保留输入、引用和阅读位置。双击正文或空白区域在新标签页打开任务 Markdown，保留看板。

提交进展后：

1. 追加一条正式进展记录。
2. 清除对应的已提交草稿。
3. 收起输入框并更新卡片上的最新进展；展示模式中继续完整展示内容。
4. 将该任务移至当前所属分组或象限顶部，其他任务相对顺序不变。
5. 更新右侧任务历史，最新记录在顶部；若正在浏览旧记录，保留阅读位置并提供“有新进展”跳转入口。

记录进展直接使用展开卡片中的编辑区，无需先进入历史。分组、象限、完成等独立控件不应误触发进展编辑。

### 3.4 可选待办与截止日期（0.3.0）

- 每张任务可独立选择无附加信息、只有待办、只有截止日期或两者都有；新建时均不预设。未添加的内容不显示空标签。
- 待办为单层清单，可添加、改文案、勾选／取消、删除并在提示中撤销删除；保留原有顺序与勾选状态。清单勾完不自动结束任务，也不覆盖最新正式进展。
- 已结束任务的清单可展开只读查看，重开后恢复编辑。完成时仍有未勾选项需提示剩余数量，由用户决定返回或继续完成；不自动勾选。
- 截止日期精确到本地日历日，可设置、改期和清除，不强制未来日期；已结束任务也可修改。卡片显示当前日期，有逾期时同时标明文字状态。
- 默认紧凑模式下同一显示条件的收起卡片等宽等高：标题单行、标签与日期横排、最新进展固定两行占位；详情和完整待办在展开后显示，底部保留完成计数。展开卡片按内容自然增高，不取整为固定网格高度。

### 3.5 展示模式与动效

- 展示模式完整显示当前筛选内全部卡片内容，但只允许一张卡片进入编辑；“结束编辑”保留完整阅读与草稿。
- 模式选择持久保存，取代旧“紧凑任务卡片”设置。关闭展示模式后正在编辑的卡片暂时保持展开，结束编辑后恢复等高。
- 模式切换保留筛选、排序、缩放、输入节点、中文组合输入、草稿与时间线阅读位置。
- 卡片展开／收起、待办进度和新增时间线记录提供短动效，支持系统减少动态效果。成功反馈以实际写入或同步回执为准，失败保留内容，旧回调不得关闭新会话。
- 详细规则见[展示模式](design/presentation-mode.md)、[卡片动效](design/card-motion-implementation.md)和[快捷反馈](design/quick-feedback-motion.md)。

## 4. 已确认：草稿

- 每个任务独立持久保存进展和详情草稿。
- 切换卡片时自动保留草稿，不弹出提交或放弃确认。
- 草稿自动保存到本地，关闭或重启 Obsidian 后仍可恢复。
- 草稿不进入正式时间线，也不作为已发生的进展提供给 AI。
- 正式提交后，写入任务历史并清除该任务草稿。
- 正常完成或异常关闭任务时，直接保留未提交草稿，不自动提交、不额外弹出草稿确认。
- 异常关闭仍必须填写关闭原因，该原因与未提交草稿分开处理。
- 重新打开任务后，可继续编辑原草稿。
- 已结束期间进展草稿只保留，不允许编辑；必须先重开才能继续记录进展。详情仍可通过菜单编辑并留痕。
- 新建草稿与上述任务草稿不同：插件新建草稿按 App／任务目录保留到本次 vault 会话结束；桌面新建草稿按仓库／目录持久保存。新建表单支持清空及撤销，不能承诺插件新建草稿跨重启恢复。

## 5. 已确认：分组、象限与排序

### 5.1 分组管理

- 支持新建、改名、排序和删除业务分组。
- 删除分组不删除任务；其中任务归入“未分组”，状态和历史保留。
- 删除分组导致任务归属变化时，记录属性变更及原因。
- 分组改名后，当前任务显示新的分组名称；过去事件保留事件发生时的分组名称，不随改名回写。
- 分组改名单独记录分组 ID、旧名称、新名称及提交时间；不向每个所属任务重复追加改名事件。分组级历史的具体存储与时间线归属在技术方案中确定。

### 5.2 拖动

- 同一区域内拖动：调整卡片顺序。
- 分组视图中跨分组拖动：修改任务所属业务分组。
- 四象限视图中跨象限拖动：修改任务的重要、紧急属性。
- 跨分组或象限变更需要留痕；单纯手动排序不记录历史。

### 5.3 排序持久化

- 默认按最近进展时间倒序排列。
- 允许手动拖动调整顺序，手动顺序保存到本地，重启后保留。
- “临时调整”表示顺序可被后续进展更新改变，不表示重启后丢弃。
- 新进展只将对应任务置顶，其他任务相对顺序不变。
- 不设一个阻止新进展置顶的永久手动排序模式。
- 分组视图和四象限视图分别保存顺序；新进展在两个视图各自所属区域置顶。
- 新建、重开任务置顶；跨区域拖动保留落点；改名不改变顺序。

## 6. 已确认：状态、改名与结束

| 状态 | 含义 | 主画面位置 |
| --- | --- | --- |
| 进行中 | 仍需推进 | 主待办卡片区 |
| 已完成 | 正常结束 | “已结束”列表入口 |
| 异常关闭 | 因取消、重复、不再需要等原因结束 | “已结束”列表入口 |

- 允许任务改名，记录旧名称、新名称和发生时间。
- 正常完成追加完成事件。
- 异常关闭必须填写原因，追加关闭原因与时间。
- 已完成与异常关闭任务都允许重新打开，恢复为进行中并追加重开事件。
- 重开保留此前进展、完成、异常关闭等全部记录。
- 已完成和异常关闭任务允许改名、调整分组及象限，按相同规则记录变更历史，任务保持已结束状态。
- 已结束任务不能直接追加进展，必须先重新打开；保留的草稿不会因属性修改而自动提交。
- 不提供任务删除、软删除、回收站或永久删除。

## 7. 已确认：历史与时间线

### 7.1 两种时间线

- 每日时间线：汇总所选日期各任务发生的事件，支持日期切换。
- 单任务时间线：展示该任务完整的跨天历史，按日期分段；可返回对话，或从活动记录入口回看每日时间线。
- 时间线是任务历史的不同视图，不另存重复的正式记录。

### 7.2 事件范围

| 事件 | 记录内容 |
| --- | --- |
| 创建 | 任务创建信息与时间 |
| 改名 | 原名称、新名称与时间 |
| 进展 | 追加的进展正文与时间 |
| 完成 | 正常完成事件与时间 |
| 异常关闭 | 关闭原因与时间 |
| 重新打开 | 恢复进行中的事件与时间 |
| 分组变更 | 变更前后归属、时间；必要时说明由分组删除引起 |
| 象限变更 | 变更前后的重要、紧急属性与时间 |
| 待办操作 | 添加、完成／取消完成、改文案、删除及撤销恢复的操作时间与内容 |
| 截止日期变更 | 原日期、新日期及操作时间；清除也留痕 |

手动排序和草稿编辑不进入正式历史。截止日的安排标记不是历史事件，不虚构未来发生时间。

### 7.3 追加与阅读规则

- 首版事件仅记录提交时间，不支持补记日期或指定过去的发生时间；草稿中的文字不用于推断或回填事件时间。
- 事件日期固定为提交时的本地日期，并保存当时的时区信息；之后设备时区变化不改变旧事件的日期归属。
- 正式进展只允许追加，不允许在插件内编辑或删除；错误通过新记录更正。
- 历史默认展示全部事件。
- 进展正文突出显示；改名、分组、象限等属性变更使用较弱样式，保留变更前后值。
- 每日与单任务时间线均按时间倒序显示，最新在上；正式存档保持原有追加顺序。
- 首次打开显示最新记录；返回已有视图或切换展示模式时保留阅读上下文。
- 正在浏览旧记录时，新事件不强制滚到顶部，提供主动查看最新的入口；不隐式切换当前查看的日期或任务。
- 全部历史逐条呈现，不折叠连续属性事件。

### 7.4 截止安排与历史的分离

- 每日时间线支持未来日期；顶部“当日截止”仅按任务**当前**截止日期投影，无符合任务时不显示。修改或清除日期后标记随之移动或消失，旧的变更事件仍留在操作发生的日期。
- 当日截止区与下方真实事件列表分别滚动；截止任务多时不得遮挡历史。单任务时间线提供当前截止摘要和“查看截止日”入口。
- 已结束任务在截止日仍显示其结束状态，不标逾期；重新打开后按本地日期重新判断。跨日时刷新今天的显示，历史事件仍按记录时的本地日期归属。

### 7.5 首版历史检索

- 支持按任务名称与进展内容进行全文搜索。
- 搜索覆盖进行中、已完成、异常关闭任务及其历史。
- 搜索结果标明命中来源、历史日期与关键词片段；进展及历史名称可直接定位原事件，当前名称和详情定位当前卡片。已结束任务直接出现在结果中；无结果时解释搜索范围并提供清除搜索入口。

## 8. 已确认：与 Obsidian 的结合及存储

### 8.1 存储职责

- 一个任务对应一篇 Markdown 笔记。
- Markdown 是正式任务和历史的唯一数据来源。
- 笔记主要用于阅读、检索、链接和后续 AI 分析。
- 插件执行正式修改；桌面快捷工具可原子创建新任务，既有任务修改通过持久命令交给插件串行应用。插件关闭时修改显示“已暂存”，收到正式写入回执后才确认成功。
- 普通操作无需掌握文件格式；同时支持用户直接编辑任务文件。保存后自动刷新，格式无效、未写完整或并发变化时保留源文件并暂停相关写入，修正后恢复。备份可显示最近有效状态，不自动覆盖正在编辑的源文件。
- 草稿、排序和界面偏好保存在插件数据中；分组及分组级事件保存在 `_groups.md`，均不混入单任务正式进展。

### 8.2 目录方案

默认任务目录为 `工作记录/任务/`，应允许配置。以下使用 Obsidian 默认配置目录举例：

```text
Obsidian 仓库/
├── 工作记录/
│   └── 任务/
│       ├── agent.md           ← AI 只读规则，不是任务笔记
│       ├── _groups.md
│       ├── 2026-09-26 完成支付模块.md
│       └── 2026-09-26 完成支付模块（2）.md
└── .obsidian/
    └── plugins/
        └── work-timeline/
            ├── manifest.json
            ├── main.js
            ├── styles.css
            └── data.json
```

- 任务使用“原始创建日期 + 任务名称”文件名，内部保留固定 ID；同日同名追加序号，非法文件名字符替换，过长名称截短。
- 不按业务分组或象限拆文件夹。
- 插件改名按可编辑协议更新默认文件名及关联材料目录，保留用户已手动指定的文件名，原创建日期与身份不变；换组、完成、异常关闭不移动文件。
- 不要求额外生成每日日记副本。

### 8.3 正式记录格式要求

任务属性至少覆盖：任务 ID、名称、状态、分组、重要、紧急；待办与截止日期均为可选。当前正式格式使用 YAML 属性与 Markdown 正文，读取旧 v1 并在原始文件备份成功后迁移，详见[编辑协议](editable-tasks.md)。

事件至少保留：事件 ID、任务关联、事件类型、准确时间、内容；属性变更还要保留变更前后的值。格式须同时适合人阅读和程序解析。具体 Markdown 与属性字段协议在实现设计中确定。

插件不提供历史修改入口，但不能阻止用户通过 Obsidian 或外部工具直接修改文件，因此不能将此设计视为不可篡改的审计存储。

用户删除文件后移除卡片，不自动还原；将文件移出任务目录或改为非 Markdown 后缀同样移除，移回有效任务文件时按稳定 ID 重新载入，保留既有草稿。分组文件无法读取时保留原文并暂停依赖分组的写入。日常备份直接复制原文，不重新序列化正式文件。

### 8.4 备份与新版初始化

已确认的备份要求：

- 数据迁移和升级前执行备份。
- 日常自动备份，保留最近 7 天的备份。
- 备份频率、范围、保存路径、恢复机制及迁移/升级前备份的保留期限，在技术方案中明确；日常 7 天保留规则不等同于已授权清理迁移/升级前备份。

历史上的 JSON → Markdown 首次切换不迁入旧 JSON 任务：先确认旧版数据备份成功，再初始化空 Markdown 档案。此规则不适用于 0.9.1 → 0.9.3 升级；现有 v1 任务、历史、附件和草稿保留。

备份失败时不得继续空数据初始化。初始化必须区分首次切换和日常启动，避免后续启动重置新版已创建的数据。原数据的备份保存及恢复机制在技术方案中明确。

### 8.5 已确认：首版运行范围

- 首版仅支持单设备使用。
- 首版不包含多设备同步、同时编辑或跨设备冲突合并能力。
- 单设备内的重复提交、多个视图写入及写入失败处理仍需保证数据一致性，具体机制在技术方案中确定。

## 9. AI 范围

### 9.1 插件内工作对话与一句话录入

- 模型仅提供回答和受限操作提议，写入前必须列明对象和变更并允许编辑确认。读操作直接回答；不自动排序、高亮、完成任务、拆分多任务或批量写入。
- 工作对话仅发送当前会话、分组名称和明确引用任务的有限上下文。任务正文中的指令按数据处理，不读取其他会话、整个 vault 或附件；一句话录入使用各自已说明的更小范围。
- 本轮长历史读取：最近 30 条作为现状上下文；按照当前问题或显式关键词／日期，从引用任务的本地完整历史补充最多 12 条较早记录。显式多个关键词全部匹配，日期按事件记录时的本地日历日判断；仅指定日期也可查找。
- 每次回答显示总历史数、匹配数与实际提供数；零匹配及结果截断明确说明。日期范围只筛选检索结果，最近历史仍单独作为现状上下文；不得声称读过未发送的历史。
- 历史来源使用稳定任务 ID／事件 ID，本地只接受本次确实发送的来源。来源按钮展示当时日期／名称，并跳转完整原记录；删除或失效来源不能阻断其他讨论，也不能继续修改该对象。
- 会话、输入、查找条件和待确认提议按 vault／任务目录隔离持久保存，不生成重复正式 Markdown。任务变化后停止过期写入，失败保留原文和操作身份，重试不重复任务／事件。
- 不配置模型或模型失败时，手动任务流程继续可用。详见[一句话说明](smart-capture.md)和[工作对话说明](design/work-conversation.md)。

### 9.2 外部 Agent 存档分析

- 任务目录提供小写 `agent.md`，默认只读：禁止 Agent 自动创建、修改、追加、改名、移动、删除或修复正式存档；只有用户明确授权的相应数据操作可执行。用户可编辑文件不等于 Agent 获得自动写入授权。
- 正式任务属性与历史可用于分析，草稿不作为已发生进展。分析输出在对话中；保存报告需使用用户指定的任务目录之外位置。
- 模板为 [只读规则](templates/agent.md)，初始化任务目录时提供；解析器和搜索排除该文件。根 `AGENTS.md` 管源码协作，两者不合并。
- 规则不等于文件系统只读权限，分析入口须明确读取并遵守，不依赖文件名自动发现。

## 10. 已采用的首版细节

- 同时只编辑一张任务卡片；展示模式可完整展开多张进行阅读，切换编辑时保存上一张草稿。
- 两种主视图共用统一已结束列表，按最近结束事件倒序显示。
- 重开保留当前分组和象限；分组不存在时归入未分组并记录原因。
- 分组配置和分组级事件保存在任务目录的 `_groups.md`；任务解析器排除该文件。
- 分组顺序持久化；排序本身不产生历史事件。
- 返回每日时间线时恢复此前选择的日期；无记录日期显示空状态。
- 全局搜索覆盖当前名称、详情和历史名称／进展；分组筛选独立于全局搜索。
- 任务草稿随输入自动保存，提交进展后清除；新建表单另提供清空与撤销入口。
- 当前 Markdown 使用 v2 YAML 属性与可编辑正文，兼容旧 v1 读取；详情和进展正文不再以完整 JSON 投影重复保存。
- 多视图任务写入经过串行队列，同一任务不会因并发写入丢失事件。
- 首次切换以插件状态标记，旧 JSON 先校验备份再从空 Markdown 档案开始。
- 每次正式写入同步更新当日备份，启动时补齐当日备份，自动保留最近 7 个备份日；迁移和升级快照不自动清理。
- 首版不实现既有笔记关联；0.4.0 支持完整导入导出，详见 2026-09-26 扩展。窄屏使用单列响应式布局。
- 0.3.0 将可选待办和截止日期连同变更事件写入原有任务 Markdown 协议；版本变化触发升级专项快照，独立原型不读写真实任务。

## 11. 核心验收场景

以下用于插件安装后的人工验收；自动化测试与构建不能代替 Obsidian 实际运行检查。

1. 新建默认“不重要不紧急”，只填写名称即可创建；创建后产生唯一任务文件和创建事件。
2. 点击任务 A，A 卡片原位展开输入框，右侧对话、输入及 @引用不变；“查看历史”才进入 A 的完整历史，返回恢复对话。
3. 在 A 输入草稿后切换到 B，再切回 A，草稿仍在；重启后仍能恢复。
4. 提交 A 的进展，输入框收起、草稿清除，A 置于当前区域顶部，其他任务相对顺序不变；右侧最新在上，浏览旧记录时保留位置。
5. 手动拖动后的顺序在重启后保留；另一任务更新进展时，仅该任务置顶。
6. 跨分组拖动修改归属并留痕；跨象限拖动修改属性并留痕；仅排序不产生事件。
7. 完成任务进入已结束区；异常关闭未填写原因不能提交。两种结束操作均保留草稿。
8. 两种已结束任务均可重开，恢复进行中并追加事件，既有历史和草稿保留。
9. 删除分组后任务归入未分组，任务文件及历史不丢失，并记录归属变更原因。
10. 右侧切换活动日期不改变左侧当前任务；活动记录与任务历史均可返回原对话，保留各自阅读位置。
11. 全部事件按时间倒序显示，属性变更弱化但不折叠；浏览旧记录时出现新事件提供跳转入口。
12. 改名按可编辑协议更新默认任务文件及已有材料目录，保留用户手动指定的文件名、原创建日期、任务 ID 与历史；完成、异常关闭及分组调整不改变路径。插件不提供删除任务或编辑、删除正式进展入口。
13. 分组与四象限视图独立保存排序；新建、重开置顶，跨区域拖动保留落点，改名不改顺序。
14. 已结束任务允许修改名称和属性，但不能编辑草稿或追加进展，重开后恢复编辑。
15. 切换设备时区不改变历史事件的日期归属；名称和进展内容搜索覆盖三种任务状态。
16. 外部编辑任务文件后自动刷新，错误格式保留原文并暂停写入，修正后恢复；删除文件移除卡片；双击及右键可打开任务文件。
17. 任务目录包含只读分析规则 `agent.md`，任务解析及搜索不将其识别为任务。
18. 旧任务和不选附加信息的新任务没有待办／日期占位；只有待办或只有截止日期的任务也能分别保存和重启读取。
19. 待办增删改、勾选和撤销删除均保留历史；删除后恢复原顺序与勾选状态，完整清单不自动完成主任务。
20. 有未完成待办时正常完成任务会提示剩余数；完成后清单只读，重开后可继续编辑，不改变已有勾选状态。
21. 截止日期可改期、清除并进入指定日期；历史保留改期事件，未来时间线只显示当前截止安排，不伪造未来事件。
22. 已结束任务的截止日显示结束状态；跨日逾期仅针对进行中任务，以本地日历日期判断。
23. 长进展和长待办在卡片展开后完整显示；收起时限制摘要并提示更多内容。桌面、窄屏及缩放下卡片不重叠。
24. 从 0.2.0 升级后先生成升级快照；旧 v1 存档原样读取，新字段、事件能在 Markdown 中往返保存。
25. 点击卡片空白、非交互正文或标题在原卡片展开／收起；编辑输入期间正文点击不收起。按钮、输入、文字选择与拖动不会额外触发展开。
26. 右键与三点菜单共用主题一致的操作；文件夹按需创建或通过菜单打开，不增加重复的卡片快捷图标。重复打开不重复创建、不新增进展，失败不覆盖同名文件。
27. 新任务按“原始创建日期 + 名称”命名，同日重名加序号；旧 UUID 文件和材料目录先备份再迁移，失败或中断可恢复，ID 与历史不变。
28. 完整导出包含材料文件、空目录及草稿；导入先预览、确认后写入。同 ID 跳过，不同 ID 同名另存；损坏包不写入，失败或中断恢复原数据。
29. 默认收起卡片等高，展开与展示模式按内容自然增高；顶部对齐和稳定瀑布流分别遵守原顺序，不引入卡内滚动条。模式切换不丢草稿、中文输入和阅读位置。
30. 分组过多时只展示按排序能放下的前几项，其余在“更多分组”中按顺序选择；长名称、窄屏及键盘操作不越界。
31. 长历史对话可以查找三十条以前的相关决定；关键词、日期范围、零结果和截断可见，来源定位到原事件，往返保留草稿；未引用对象和未发送来源不能进入回答依据。

## 12. 当前实现

当前发布基线为 0.9.7，使用版本化可编辑 Markdown 任务协议，实现工作对话、统一创建入口、四象限、卡片内输入、持久草稿、双视图独立排序、异常关闭、完整属性留痕、可选待办与截止日期、搜索、备份恢复和分组级历史。`loadData / saveData` 保存草稿、会话、模型配置、排序、视图偏好和初始化标记，不再保存正式任务或事件。

## 2026-10-16 · 1.0 工作台

展示台是包含任务标题与操作的完整玻璃卡片，左侧竖排进展／待办／详情／目录缩略图与文字，悬停预览，拖入右侧加入；单击不新增。右侧支持列与列内行，插入后默认均分，分界线可拖动或用方向键调整。一个模块保留一份，重复拖入表示移动；收回不删除内容与草稿。默认进展一列、待办与详情一列，有材料目录时默认增加目录列；自定义布局优先于自动目录列。

布局以任务目录和稳定任务 ID 为键存入插件 `data.json` 的 `stageLayouts`，改名不失效、切卡恢复，撤销与恢复默认只作用当前任务；不修改正式 Markdown／历史协议。窄屏顺排，长内容自然撑高，手动行高比例不用于裁切正文。

背景偏好独立存入 `background`：银灰、山景、建筑或自定义 PNG/JPG/WebP/AVIF（8 MB 以内），支持明暗与柔焦。自定义图片作为 data URL 随本地插件配置保存，不上传远程；摄影预设联网读取，失败显示银灰。切换不重建编辑节点或清草稿。配置保存失败保留先前有效值并允许重试。

牌组标题、工具、两轴筛选和封面共享圆角玻璃边界，封面等尺寸，边缘圆角并淡出。一个任务一张，首尾停止；浏览与选中分离，引用不跟随浏览。任务／分组 Emoji 与选择入口移除，旧属性及历史只兼容保留。负责人和行动提醒仍为独立设计提案，未因本次发布扩大为实现范围。

桌面快捷工具同步这套界面语言：离线银灰折光背景、磨砂阅读面板、圆角标签与输入控件，覆盖新建、直接进展、任务选择、一句话创建及模型设置；macOS／Windows 共用本地资源。沿用两种顶层入口、图文草稿、独立任务草稿、IME 策略和真实回执；屏幕有空间时按内容测量窗口，短屏表单独立滚动、底部操作可达，后台逐帧回调暂停时仍能准备下一次窗口尺寸。照片／自定义背景仍是插件工作台偏好。
