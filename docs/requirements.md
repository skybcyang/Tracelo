# 工作时间线插件需求文档

更新日期：2026-09-18  
状态：首版已实现。本文同时作为业务规则与验收基线。

## 1. 产品目标

在 Obsidian 内，以任务卡片呈现当前有哪些事情要做、每件事推进到了哪里；通过每日时间线与单任务时间线保留工作过程，并为后续 AI 分析积累可读取的结构化历史。

主画面优先呈现当前待办和最新进展。任务跨天持续存在，不因日期切换而重复创建。

## 2. 已确认：主画面与视图

- 左侧以任务卡片为主体，右侧常驻时间线，两者同时展示。
- 左侧支持“分组视图”和“四象限视图”切换，共享同一批任务。
- 分组视图按业务分组展示任务；四象限视图按重要、紧急两个独立属性展示任务。
- 四个象限为：重要且紧急、重要不紧急、紧急不重要、不重要不紧急。不再使用高、中、低单一优先级。
- 所有进行中的任务持续显示，直到正常完成或异常关闭。
- 页面底部设统一的“已结束”折叠区，默认收起，包含已完成与异常关闭任务，明确区分两种状态。
- 右侧切换日期只影响每日时间线，左侧始终显示当前待办及最新进展。

## 3. 已确认：任务卡片与新建

### 3.1 卡片信息

卡片呈现任务名称、最新进展、业务分组、重要与紧急属性以及任务状态。无需打开详情即可了解当前进展。

### 3.2 新建

- 通过弹窗新建任务。
- 创建时必须主动选择一个象限，不预选象限。
- 创建任务时记录创建事件。
- 名称必填，业务分组可选，默认“未分组”；允许填写初始进展，填写时作为独立进展事件追加。

### 3.3 点击与提交

点击任务卡片，同时执行：

1. 卡片本身展开进展输入框。
2. 右侧切换为该任务跨天的完整历史。

提交进展后：

1. 追加一条正式进展记录。
2. 清除对应的已提交草稿。
3. 收起输入框并更新卡片上的最新进展。
4. 将该任务移至当前所属分组或象限顶部，其他任务相对顺序不变。
5. 更新右侧任务历史，自动滚动到底部。

记录进展无需再点击独立的“历史”入口。分组、象限、完成等独立控件不应误触发进展编辑。

## 4. 已确认：草稿

- 每个任务独立保存草稿。
- 切换卡片时自动保留草稿，不弹出提交或放弃确认。
- 草稿自动保存到本地，关闭或重启 Obsidian 后仍可恢复。
- 草稿不进入正式时间线，也不作为已发生的进展提供给 AI。
- 正式提交后，写入任务历史并清除该任务草稿。
- 正常完成或异常关闭任务时，直接保留未提交草稿，不自动提交、不额外弹出草稿确认。
- 异常关闭仍必须填写关闭原因，该原因与未提交草稿分开处理。
- 重新打开任务后，可继续编辑原草稿。
- 已结束期间草稿只保留，不允许编辑；必须先重开才能继续编辑。

## 5. 已确认：分组、象限与排序

### 5.1 分组管理

- 支持新建、改名、排序和删除业务分组。
- 删除分组不删除任务；其中任务归入“未分组”，状态和历史保留。
- 删除分组导致任务归属变化时，记录属性变更及原因。
- 分组改名后，当前任务显示新的分组名称；过去事件保留事件发生时的分组名称，不随改名回写。
- 分组改名单独记录分组 ID、旧名称、新名称及提交时间；不向每个所属任务重复追加改名事件。分组级历史的具体存储与时间线归属在技术方案中确定。

### 5.2 拖动

- 同一区域内拖动：调整卡片顺序。
- 分组视图中跨分组拖动：修改任务所属业务分组。
- 四象限视图中跨象限拖动：修改任务的重要、紧急属性。
- 跨分组或象限变更需要留痕；单纯手动排序不记录历史。

### 5.3 排序持久化

- 默认按最近进展时间倒序排列。
- 允许手动拖动调整顺序，手动顺序保存到本地，重启后保留。
- “临时调整”表示顺序可被后续进展更新改变，不表示重启后丢弃。
- 新进展只将对应任务置顶，其他任务相对顺序不变。
- 不设一个阻止新进展置顶的永久手动排序模式。
- 分组视图和四象限视图分别保存顺序；新进展在两个视图各自所属区域置顶。
- 新建、重开任务置顶；跨区域拖动保留落点；改名不改变顺序。

## 6. 已确认：状态、改名与结束

| 状态 | 含义 | 主画面位置 |
| --- | --- | --- |
| 进行中 | 仍需推进 | 主待办卡片区 |
| 已完成 | 正常结束 | 底部“已结束”区 |
| 异常关闭 | 因取消、重复、不再需要等原因结束 | 底部“已结束”区 |

- 允许任务改名，记录旧名称、新名称和发生时间。
- 正常完成追加完成事件。
- 异常关闭必须填写原因，追加关闭原因与时间。
- 已完成与异常关闭任务都允许重新打开，恢复为进行中并追加重开事件。
- 重开保留此前进展、完成、异常关闭等全部记录。
- 已完成和异常关闭任务允许改名、调整分组及象限，按相同规则记录变更历史，任务保持已结束状态。
- 已结束任务不能直接追加进展，必须先重新打开；保留的草稿不会因属性修改而自动提交。
- 不提供任务删除、软删除、回收站或永久删除。

## 7. 已确认：历史与时间线

### 7.1 两种时间线

- 每日时间线：汇总所选日期各任务发生的事件，支持日期切换。
- 单任务时间线：展示该任务完整的跨天历史，按日期分段，可返回每日时间线。
- 时间线是任务历史的不同视图，不另存重复的正式记录。

### 7.2 事件范围

| 事件 | 记录内容 |
| --- | --- |
| 创建 | 任务创建信息与时间 |
| 改名 | 原名称、新名称与时间 |
| 进展 | 追加的进展正文与时间 |
| 完成 | 正常完成事件与时间 |
| 异常关闭 | 关闭原因与时间 |
| 重新打开 | 恢复进行中的事件与时间 |
| 分组变更 | 变更前后归属、时间；必要时说明由分组删除引起 |
| 象限变更 | 变更前后的重要、紧急属性与时间 |

手动排序和草稿编辑不进入正式历史。

### 7.3 追加与阅读规则

- 首版事件仅记录提交时间，不支持补记日期或指定过去的发生时间；草稿中的文字不用于推断或回填事件时间。
- 事件日期固定为提交时的本地日期，并保存当时的时区信息；之后设备时区变化不改变旧事件的日期归属。
- 正式进展只允许追加，不允许在插件内编辑或删除；错误通过新记录更正。
- 历史默认展示全部事件。
- 进展正文突出显示；改名、分组、象限等属性变更使用较弱样式，保留变更前后值。
- 每日与单任务时间线均按时间正序排列，最早在上。
- 打开时间线时定位到最新记录，即底部。
- 当前时间线视图出现任何新记录时都自动滚动到底部，即使用户正在浏览旧记录。
- 自动滚动不意味着自动切换当前查看的日期或任务。

### 7.4 首版历史检索

- 支持按任务名称与进展内容进行全文搜索。
- 搜索覆盖进行中、已完成、异常关闭任务及其历史。

## 8. 已确认：与 Obsidian 的结合及存储

### 8.1 存储职责

- 一个任务对应一篇 Markdown 笔记。
- Markdown 是正式任务和历史的唯一数据来源。
- 笔记主要用于阅读、检索、链接和后续 AI 分析。
- 新建、改名、记录进展、属性变更、结束与重开统一通过插件操作。
- 用户不需要掌握文件格式；手工编辑不是受支持的任务操作流程。
- 草稿、分组配置、排序和界面偏好保存在插件数据中，不混入正式事件。

### 8.2 目录方案

默认任务目录为 `工作记录/任务/`，应允许配置。以下使用 Obsidian 默认配置目录举例：

```text
Obsidian 仓库/
├── 工作记录/
│   └── 任务/
│       ├── agent.md           ← AI 只读规则，不是任务笔记
│       ├── <固定任务ID>.md
│       └── <固定任务ID>.md
└── .obsidian/
    └── plugins/
        └── work-timeline/
            ├── manifest.json
            ├── main.js
            ├── styles.css
            └── data.json
```

- 任务使用固定 ID 文件名；显示名称存入任务属性。
- 不按业务分组或象限拆文件夹。
- 改名、换组、完成、异常关闭不移动任务文件，保持路径稳定。
- 不要求额外生成每日日记副本。

### 8.3 正式记录格式要求

任务属性至少覆盖：任务 ID、名称、状态、分组、重要、紧急。

事件至少保留：事件 ID、任务关联、事件类型、准确时间、内容；属性变更还要保留变更前后的值。格式须同时适合人阅读和程序解析。具体 Markdown 与属性字段协议在实现设计中确定。

插件不提供历史修改入口，但不能阻止用户通过 Obsidian 或外部工具直接修改文件，因此不能将此设计视为不可篡改的审计存储。

已确认：任务文件因外部修改等原因无法解析、发生可解析的手工修改或被外部删除时，自动使用该任务最近一次有效备份恢复到插件管理的有效状态，避免外部操作绕过留痕规则。插件自身的正常写入不触发此恢复逻辑。

- 恢复前保留外部修改版本（如文件仍存在），防止丢失备份之后尚可找回的内容。
- 候选备份须通过格式及任务身份校验；最新备份无效时继续查找更早的有效备份。
- 仅恢复受影响任务，不回滚其他正常任务。
- 恢复后提示具体文件和备份时间，说明备份之后的修改可能未包含在恢复结果中。
- 没有有效备份或恢复失败时，保留原文件、暂停该任务写入并提示，不以空数据替代；其他任务正常使用。

### 8.4 备份与新版初始化

已确认的备份要求：

- 数据迁移和升级前执行备份。
- 日常自动备份，保留最近 7 天的备份。
- 备份频率、范围、保存路径、恢复机制及迁移/升级前备份的保留期限，在技术方案中明确；日常 7 天保留规则不等同于已授权清理迁移/升级前备份。

已确认：本次切换到 Markdown 存储时，不迁移旧任务。先备份旧版数据，确认备份成功后，新版从空数据开始，不导入旧任务及其历史。

备份失败时不得继续空数据初始化。初始化必须区分首次切换和日常启动，避免后续启动重置新版已创建的数据。原数据的备份保存及恢复机制在技术方案中明确。

### 8.5 已确认：首版运行范围

- 首版仅支持单设备使用。
- 首版不包含多设备同步、同时编辑或跨设备冲突合并能力。
- 单设备内的重复提交、多个视图写入及写入失败处理仍需保证数据一致性，具体机制在技术方案中确定。

## 9. AI 范围

AI 直接只读分析存档 Markdown 文件，无需在首版插件内接入模型服务。可读取正式任务属性和完整事件，草稿不纳入分析。

- 任务目录必须提供 `agent.md`，明确禁止 agent 直接创建、修改、覆盖、追加、改名、移动或删除该目录的文件；任务变更统一由用户通过插件执行。
- 分析结果输出在对话中；如需保存报告，应由用户指定任务目录之外的位置，不写回存档。
- 项目中的规则模板为 `docs/templates/agent.md`，实现目录初始化时将其放到配置的任务目录。它不是任务数据，任务解析器应排除该文件。
- 规则文件是供 agent 阅读遵守的约定，不等于文件系统只读权限；分析入口须确保 agent 读取该规则，不依赖文件名自动发现。
- 本次仅确定分析方式，不执行 AI 分析，也不增加自动上传、模型服务配置或 AI 修改任务能力。

## 10. 已采用的首版细节

- 同时只展开一张任务卡片；切换时保存上一张草稿。
- 两种主视图共用统一已结束列表，按最近结束事件倒序显示。
- 重开保留当前分组和象限；分组不存在时归入未分组并记录原因。
- 分组配置和分组级事件保存在任务目录的 `_groups.md`；任务解析器排除该文件。
- 分组顺序持久化；排序本身不产生历史事件。
- 返回每日时间线时恢复此前选择的日期；无记录日期显示空状态。
- 首版只提供任务名与进展全文搜索，不增加组合筛选器。
- 草稿随输入自动保存，不提供独立清空入口；提交进展后清除。
- Markdown 使用版本化 JSON 数据块和可读投影；任何非插件改写都会触发备份恢复。
- 多视图任务写入经过串行队列，同一任务不会因并发写入丢失事件。
- 首次切换以插件状态标记，旧 JSON 先校验备份再从空 Markdown 档案开始。
- 每次正式写入同步更新当日备份，启动时补齐当日备份，自动保留最近 7 个备份日；迁移和升级快照不自动清理。
- 首版不实现导出和既有笔记关联；窄屏使用单列响应式布局。

## 11. 核心验收场景

以下用于后续实现验收，不代表当前版本已通过。

1. 新建弹窗未选择象限时不能创建；创建后产生唯一任务文件和创建事件。
2. 点击任务 A，A 卡片展开输入框，右侧显示 A 的完整历史。
3. 在 A 输入草稿后切换到 B，再切回 A，草稿仍在；重启后仍能恢复。
4. 提交 A 的进展，输入框收起、草稿清除，A 置于当前区域顶部，其他任务相对顺序不变，右侧滚动到底部。
5. 手动拖动后的顺序在重启后保留；另一任务更新进展时，仅该任务置顶。
6. 跨分组拖动修改归属并留痕；跨象限拖动修改属性并留痕；仅排序不产生事件。
7. 完成任务进入已结束区；异常关闭未填写原因不能提交。两种结束操作均保留草稿。
8. 两种已结束任务均可重开，恢复进行中并追加事件，既有历史和草稿保留。
9. 删除分组后任务归入未分组，任务文件及历史不丢失，并记录归属变更原因。
10. 右侧切换历史日期不改变左侧当前任务；从任务历史可返回每日时间线。
11. 全部事件按时间正序显示，属性变更弱化；当前视图新增事件后自动到底部。
12. 改名、完成、异常关闭及分组调整不改变任务文件路径；插件不提供删除任务或编辑、删除正式进展入口。
13. 分组与四象限视图独立保存排序；新建、重开置顶，跨区域拖动保留落点，改名不改顺序。
14. 已结束任务允许修改名称和属性，但不能编辑草稿或追加进展，重开后恢复编辑。
15. 切换设备时区不改变历史事件的日期归属；名称和进展内容搜索覆盖三种任务状态。
16. 外部修改或删除任务文件后按备份恢复规则处理，保留可找回的外部版本；无有效备份时提示并暂停该任务写入。
17. 任务目录包含只读分析规则 `agent.md`，任务解析及搜索不将其识别为任务。

## 12. 当前实现

当前源码已使用版本化 Markdown 任务协议，实现四象限、卡片内输入、持久草稿、双视图独立排序、异常关闭、完整属性留痕、搜索、备份恢复和分组级历史。`loadData / saveData` 只保存草稿、排序、视图偏好和初始化标记，不再保存正式任务或事件。
