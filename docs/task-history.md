- 配套模式：固定尺寸用于默认紧凑模式；开启下述“展示模式”后解除高度限制，全部卡片完整展示。

## 展示模式：全部展开阅读、单卡编辑

- 记录日期：2026-09-30
- 状态：设计与源码实施完成，自动交互验证通过；真实 Obsidian 全量验收尚未完成。
- 目标：与“收起卡片固定尺寸”配套，默认模式用于等高速览，展示模式用于完整阅读；信息展开与进入编辑分别控制。
- 参考：沿用旧版展示模式的阅读／编辑分离思路，基于当前最新界面实现，不恢复旧版整体布局。

### 入口与显示规则

- 第二行看板工具栏右侧、“今天截止”筛选之前，增加常驻「展示模式」切换按钮；与分组／四象限、分组筛选及缩放独立组合使用。
- 使用展开线性图标和「展示模式」文字；关闭时为普通轻按钮，开启后使用主题色浅底与明确选中状态。开启时悬停提示“已完整展示卡片，点击恢复紧凑显示”，支持键盘操作与可访问的开关状态。
- 默认关闭，使用等高收起卡片；记住用户上次选择，重载后恢复。
- 开启后，当前筛选范围内的全部卡片默认完整展示标题、最新进展、详情、图片、待办与截止日期，高度随内容自然增长；切换筛选或新出现的卡片沿用该模式。
- 展示模式取消两行空占位；没有进展、详情或待办时不显示对应区域，不增加卡片内部滚动条。图片等比例显示，支持原有大图预览。
- 完整展示仅指当前卡片内容，全部历史仍在右侧时间线查看，不铺进卡片。
- 保留当前响应式列宽、缩放、任务顺序及布局偏好；瀑布流下按稳定列排列不同高度卡片，不因切换模式重新按高度排序。

### 阅读与编辑交互

- 开启后不自动打开进展输入框或添加待办等编辑入口；点击某张卡片或其「记录进展」才进入该卡片编辑，同一时间只编辑一张，其他卡片保持完整展示。
- 展示模式中的关闭编辑按钮使用「结束编辑」；结束编辑只关闭编辑区、保留草稿，不收起卡片内容，并恢复合理焦点。
- 提交成功后关闭输入区、继续完整展示卡片；失败保留输入和重试入口。已结束任务不显示进展输入框。
- 待办可直接勾选；选择文字、打开链接、图片预览及卡内按钮操作不误触进入编辑。
- 模式切换保留筛选、缩放、选中任务、任务顺序及草稿，不触发提交；右侧时间线保留节点、日期与阅读位置。
- 高度变化时以当前阅读卡片为锚点，避免看板突然回到顶部；关闭展示模式时，其余卡片恢复等高，正在编辑的卡片保持展开，结束编辑后再恢复等高。
- 将设置中的「紧凑任务卡片」合并进此按钮，避免两个开关互相覆盖；实施时处理已有偏好的兼容，不改变任务存档内容。

## 截止日历大弹窗

- 记录日期：2026-09-29
- 状态：功能已实现并通过自动验证；真实 Obsidian 跨月、空日期、今天与任务跳转已复核，完整焦点／布局矩阵待补齐。
- 目标：一眼看到整个月有哪些截止任务，并查看某一天的完整任务列表。

### 已确认的设计

在主页面右上角增加日历图标，点击打开一个较大的弹窗。弹窗覆盖在主页面上，保留遮罩后的主页面背景，**不替代主页面，也不作为新的看板视图**。

弹窗结构：

- 顶部：标题“截止日历”、当前年月、上个月／下个月、“今天”和关闭按钮。
- 左侧约占 2/3：月历，周一为一周起点；日期格子直接展示任务名称摘要，不只显示圆点或数量。
- 右侧约占 1/3：所选日期及星期、当天截止任务数量、完整任务列表。
- 底部：简短说明“按任务截止日期显示”。mockup 中的“示例数据”仅用于预览，不进入正式界面。

月历与列表：

- 首次打开显示当前月份，默认选中今天。
- 今天用醒目的日期标记表示；选中日期用浅色背景和边框表示，两种状态可区分。
- 每格先显示两条任务名称，长名称省略；更多任务显示“+N 项”。右侧列表展示该日全部任务与完整名称。
- 点击日期只更新弹窗中的选中日期及任务列表，不改变主页面的筛选、排序、选中任务或时间线日期。
- “今天”回到当前月份并选中今天；月份切换提供前后浏览。
- 右侧任务条目显示任务名称、分组及状态；点击任务复用现有任务查看入口。
- 右上角关闭、点击遮罩或 Esc 可退出。普通关闭后，主页面保留原滚动位置、草稿和阅读状态，焦点返回日历入口。

视觉沿用现有 Tracelo 的蓝灰配色、浅色面板、细分隔线和紧凑控件，兼容深色模式。弹窗应足够宽，使月历任务摘要可读；窄窗口将当天列表放到月历下方，不强行压缩成两列。

### 数据与范围

- 自动读取任务已有的 `dueDate`，无需再次添加到日历。
- 日期含义固定为“截止日”，不解释为计划执行日或开始时间。
- 没有截止日期的任务不进入月历，不强制用户补日期。
- 日期按本地日历日处理；正式界面使用实际今天，不沿用 mockup 固定的示例日期。
- 沿用每日时间线的日期与状态语义：已完成／已关闭任务仍能在其截止日查看，以弱化样式和文字区分，不标记为逾期。
- 修改截止日期后，日历条目移动到新日期；清除日期后条目消失，原有变更历史保留。
- 复用现有任务存档与状态，不另建日历事件，也不迁移存档格式。

第一版不加入入口数字角标、额外筛选、独立逾期汇总、通知提醒、拖拽改期、开始时间、跨天排期、重复任务或外部日历同步。

## 桌面快捷记录进展与统一卡片样式

- 记录日期：2026-09-29
- 状态：共享卡片、双端入口与持久命令协议已实现，自动验证通过；双平台实机交互验收待完成。

### 已确认的设计

**记录进展复用插件内展开后的任务卡片。** 快捷窗口中的卡片可以比看板卡片更宽，当前 mockup 采用 600 px；内部内容顺序、字号、间距与操作以插件原卡片为准，不另设计一套进展表单。

- 保留任务名称、详情、最新进展、待办清单、完成计数、截止日期、重要／紧急属性及时间等已有内容；没有配置的可选内容不显示空占位。
- 保留展开卡片中的待办勾选、添加、编辑及原有任务操作入口；相关写入能力需要与正式跨端协议一起接入。
- 底部沿用“记录当前进展”输入框、“收起”和“记录进展”按钮。
- 窗口外层提供任务选择／切换、快捷入口切换及收起能力。

**新建任务保留原来的完整表单结构，采用卡片样式。** 不使用早期 mockup 中只有名称和详情的简化表单，也不以新建弹窗样式反向改造进展卡片。

- 字段、顺序及交互保持不变：任务名称、详情、任务分组、2×2 四象限，以及按需展开的待办、截止日期和初始进展。
- 草稿提示、清空草稿、取消、创建任务及提交快捷键继续保留。
- 背景、边框、圆角、阴影、字号、输入框、按钮和选中状态与卡片统一；浅色为白色卡片，深色沿用卡片配色。

### 快捷交互与数据规则

- 延续现有快捷创建入口；增加“记录进展”的可配置全局快捷键及菜单栏／托盘入口。`Control+Option/Alt+P` 为候选组合，正式默认值需核对冲突；原创建快捷键保持不变。
- 两个入口进入各自对应模式，窗口内可以切换“记录进展／新建任务”。
- 全局记录入口先展示最近更新的进行中任务，支持按任务名称、分组或进展搜索，方向键选择、Enter 打开卡片。正式入口不因上次选择而悄悄把文字写入另一任务；mockup 首屏直接展示示例卡片仅为便于评审。
- 选定任务后聚焦进展输入；Enter 换行，macOS 用 Command+Enter、Windows 用 Ctrl+Enter 记录。中文输入法组合期间不提交。
- 进展草稿按任务独立保存；切换任务、切换模式、Esc 或“收起”均不自动提交。再次打开可恢复对应草稿；新建草稿与进展草稿分别管理。

## 新建卡片与快捷创建：详情粘贴图片

- 记录日期：2026-09-29
- 状态：共享图文草稿和三端附件写入已实现，自动生命周期验证通过；真实剪贴板／文件选择器验收待完成。
- 目标：在插件内新建卡片及 macOS／Windows 快捷创建时，直接在详情中粘贴截图，图片随草稿保留并随任务保存。
- 范围：两个创建入口共用同一套表单与交互规则；与上文“桌面快捷记录进展与统一卡片样式”配套，保留原完整表单、字段顺序和四象限布局。

### 设计方案

采用“现有 Markdown 输入＋图片缩略图预览”。继续在详情正文中保存图片引用，下方提供可见预览，不扩展为完整富文本编辑器。

| 区域 | 设计与交互 |
|------|------------|
| 详情输入框 | 默认两行，保留“详情／可选”标签；占位提示“补充目标、要求或参考资料，可直接粘贴图片”。 |
| 图片入口 | 输入框下增加“添加图片”轻按钮与“支持粘贴或拖入”提示；使用现有图标和主题样式，不露出原生文件选择器外观。 |
| 图片预览 | 有图片才显示；缩略图约 72 × 56px，完整适配、不裁切，附简短名称、处理状态与移除操作。 |
| 多图布局 | 按正文引用顺序排列；超过两行后局部滚动并显示总数，避免撑大快捷窗口。 |
| 大图查看 | 点击缩略图放大；关闭按钮或 Esc 退出，焦点回到原缩略图。 |
| 底部操作 | 延续现有取消、创建与快捷键；表单正文独立滚动，创建按钮始终可见。 |

快捷创建与插件内创建拥有相同的图片能力，沿用各自窗口管理和焦点恢复方式。深色、窄窗口、触屏和键盘操作均需适配；图片操作不能只在悬停时出现。

### 插入、编辑与状态规则

- 详情获得焦点时，⌘V／Ctrl+V 在当前光标或选区插入图片引用，前后按需补换行；其余文字不丢失，插入后可继续输入。标题和初始进展等字段不把图片隐式转入详情。
- “添加图片”支持多选，使用打开文件选择器前的光标位置；取消选择不改变内容。拖入时只突出详情落点，无法识别具体文本落点时追加到详情末尾。
- 图片接收后立即显示缩略图和“处理中…”，处理完成后隐藏状态文字；允许继续输入，多图完成顺序不能改变正文顺序，处理结束时不能按新光标位置插错内容。
- 纯文字和 Markdown 原样粘贴；普通图片 URL 保持文字，不主动下载。同一剪贴板图片的文件／HTML 表示只插入一次；混合图文不能静默丢掉文字，未能导入的图片提供明确提示。
- 移除同步删除对应正文引用与预览项，支持撤销；手动删除引用及键盘撤销也保持一致。仍被其他位置引用的图片不能误删，迟到的处理结果不能恢复已移除内容。
- 处理中暂不可创建，并说明“正在处理 N 张图片”；处理失败就地提供原因、重试和移除。存在未解决失败项时不允许悄悄忽略图片创建，按钮和提交快捷键遵守相同规则。
- 创建时显示“创建中…”并阻止重复提交；失败保留所有图文与字段，重试不生成重复卡片或重复附件；成功后才清空草稿、关闭窗口。
- 支持格式及容量限制在实现阶段结合三个宿主验证；界面提示必须与实际能力一致，不预先承诺未经验证的格式。

### 草稿与附件归属

- 图片先归属新建草稿，创建成功后才归属正式任务；不能为了接收图片提前创建正式卡片。
- Esc、关闭或取消时，文字与已接收图片一起保留，再次打开恢复真实状态；切换快捷窗口的“新建任务／记录进展”模式也不丢新建图文草稿。
- 草稿按宿主、仓库和保存位置隔离，新建草稿与各任务的进展草稿分别管理，不能串稿。
- 图片保留周期必须与文字一致。当前插件最低基线为本次 vault 会话；上文快捷工具的持久化草稿任务实施后，图片也必须支持退出重开恢复，不能只恢复失效引用。
- “清空草稿”同时清空图文，并提供一次整体撤销；撤销窗口内保留必需图片。清空后的异步结果不能把旧内容重新插回。
- 创建时将图片存入任务材料目录，正文使用兼容现有 Markdown 的引用；保存成功必须意味着正文和全部本地图片均可靠保存，不能依赖临时预览地址。
- 若快捷工具在 Obsidian 未运行时采用暂存再同步，应同时保留图片内容，并明确区分“已暂存”和“已写入任务”，不能提前宣称正式创建成功。
- 清理只处理明确属于本草稿且不再被引用或撤销记录需要的临时文件，不删除原图、已有任务附件或其他草稿资源。
