# 新建卡片：详情粘贴图片设计

日期：2026-09-29。本文保留开发前的设计提案与当时依据；功能随后已实现并纳入 0.9.1。当前协议见[任务上下文协议](task-context-protocol.md)，实施与验证见[四组功能验证](../validation/2026-09-29-all-tasks.md)，0.9.3 发布边界见[发布验收](../validation/2026-09-30-release-093.md)。下文“没有处理／尚未执行”描述的是提案时点。

## 推荐方向

保留现有紧凑新建表单和 Markdown 输入，在详情区域增加「添加图片」、粘贴与拖入能力，以及图片缩略图。用户可以先写说明，在光标处贴一张截图，然后继续写；创建后的详情按正文顺序显示图片。

本轮采用交互规格交付，不制作新的可运行原型。沿用现有浅色／深色、品牌蓝、控件样式和表单字段顺序。依据交互设计原则，为快捷粘贴提供可发现的按钮，并明确处理中、失败、撤销和草稿恢复行为。

## 当前依据

- `src/new-task-form.ts` 的 `mountNewTaskForm`：详情是两行 textarea，没有图片选择、粘贴或拖入处理。该表单供插件和桌面工具共用。
- `src/main.ts` 的 `renderNotes`：已创建卡片的详情支持文件选择、剪贴板图片、拖入，以及 Markdown 图片渲染和点击放大。新建入口与后续编辑的能力不一致。
- `src/main.ts` 的 `NewTaskModal`：插件新建草稿为当前 vault 会话内草稿；取消和关闭保留，创建成功才清空，不能把它描述成已有跨重启恢复能力。
- `src/archive-store.ts` 的 `writeNoteAttachment`：现有图片保存依赖正式任务，并会写入任务。因此不能在新建阶段直接调用它，以免粘贴时就创建正式卡片。
- 视觉参考：现有创建表单代码和 [快捷入口设计预览](quick-progress/create-card-preview.png)。该图片是已有原型截图，不是本轮设计效果图；本轮未操作真实创建流程。

## 详情区域布局

| 从上到下 | 呈现和规则 |
| --- | --- |
| 字段标题 | 保留「详情」与「可选」 |
| 文本框 | 默认两行；提示「补充目标、要求或参考资料，可直接粘贴图片」；继续支持 Markdown |
| 轻量操作行 | 左侧「添加图片」按钮；右侧「支持粘贴或拖入」，窄屏允许换行；不加入完整富文本工具栏 |
| 图片预览区 | 有图片后才出现；缩略图约 72 × 56px，完整适配、不裁切截图文字；依正文引用顺序排列，并附简短名称、状态和移除操作 |
| 局部状态 | 图片出错时在该图片旁显示原因和「重试」「移除」，不弹出打断输入的对话框 |

预览区超过两行后在局部滚动，并显示「共 N 张」。图片不撑大整个窗口；表单中段仍可滚动，底部创建按钮持续可见。沿用现有图标库，操作不依赖悬停才可发现，键盘聚焦和触屏也可使用。

第一版继续显示 Markdown 图片引用，同时用缩略图确认贴入结果。这与现有详情编辑方式一致，代价是编辑时仍会看到图片语法；正文内直接显示可编辑图片属于之后单独评估的编辑器升级。

## 粘贴与添加

1. **粘贴截图**：仅在详情输入区获得焦点时接管图片粘贴。macOS 使用 ⌘V，Windows 使用 Ctrl+V；标题、进展等字段不把图片偷偷转入详情。
2. **光标插入**：在当前光标／选区插入图片引用，前后按需补换行，保留其余文字。操作完成后焦点留在详情，光标位于图片引用之后。
3. **即时反馈**：先显示缩略图和「处理中…」，就绪后状态文字消失；不显示没有真实依据的百分比。期间可以继续输入，并用稳定的插入位置跟踪处理结果，不能根据处理完成时的新光标插错位置。
4. **选择文件**：「添加图片」支持多选，使用打开选择器之前的光标位置；取消文件选择不改变内容。没有历史光标位置时追加在详情末尾。
5. **拖入文件**：只把详情区域作为图片落点，拖入时突出边框并显示「松开插入图片」。落点在文本内时按可识别位置插入，否则追加末尾。不把整个弹窗变成文件接收区。
6. **多图和顺序**：一次添加多张时按输入顺序排队，即使完成顺序不同，也保持正文顺序。再次添加同一张图视为用户的第二次插入，不静默去重。
7. **普通内容**：纯文字和 Markdown 原样粘贴；普通图片 URL 保持文字，不主动下载。剪贴板同一截图的文件与 HTML 表示只插入一次。混合图文能可靠解析时保留顺序，不能解析时至少保留文字，并提示「部分图片未导入，可单独粘贴或添加图片」，不能吞掉内容。

## 预览、移除与撤销

- 点击缩略图打开大图预览；适配窗口、完整显示，支持关闭按钮和 Esc，关闭后焦点回到原缩略图。
- 「移除」同时移除对应的正文图片引用和预览项；不弹确认。提供「已移除图片 · 撤销」，且与正文的 ⌘Z / Ctrl+Z 撤销语义一致。
- 手动删除正文中的引用也应同步预览列表；撤销删除能恢复图片。仍被其他位置引用的文件不因移除一个引用而删除。
- 图片说明来自 Markdown 替代文字，截图默认名称为「截图 1」等；预览和移除按钮有包含图片名称的可访问标签。
- 处理期间移除图片后，迟到的处理结果不能把它重新插回。图片进入失败态后，重试保留原插入位置，且不重复插入。

## 状态与创建规则

| 状态 | 图片反馈 | 创建行为 |
| --- | --- | --- |
| 无图片 | 不显示预览区 | 延续现有名称必填规则 |
| 正在处理 | 对应缩略图显示「处理中…」，允许移除 | 暂不可创建；按钮附近说明「正在处理 N 张图片」；快捷键遵守相同规则 |
| 图片就绪 | 显示缩略图，可预览和移除 | 可以创建；此时图片仍属于草稿 |
| 个别图片失败 | 就地显示失败原因，支持单张重试／移除 | 存在未解决的失败项时不可创建，避免无声漏图；不影响已成功图片和文字 |
| 正在创建 | 主按钮「创建中…」，防止重复提交 | 创建完成前保持草稿，沿用现有关闭保护 |
| 创建失败 | 操作栏上方显示「创建失败，内容已保留，请重试」及可读原因 | 保留文字、图片和字段，重试不生成重复卡片或重复附件 |
| 创建成功 | 关闭表单并显示新卡片 | 清空本次草稿；详情中的图片可正常打开 |

格式错误在该图片上说明「暂不支持此图片格式，请转换为 PNG、JPG 或 WebP」；读写失败说明「图片未能保存，请重试」。最终支持格式与大小限制需要在后续实现时结合三个宿主验证，界面只显示实际支持的能力，不先承诺未经验证的格式或容量。

## 草稿与文件归属

图片先归属新建草稿，创建成功后再归属正式任务。这是本方案的必要行为，具体暂存机制留给实现决定。

- Esc、关闭、取消：文字与已接收图片一起保留，再次打开恢复。关闭正在处理的草稿后，已接收的图片继续归属同一草稿；恢复时展示真实处理状态。
- 草稿至少遵守当前宿主已有的保留周期；插件最低范围是本次 vault 会话，不能提示跨重启保证。若桌面宿主支持持久草稿，图片必须具有相同的恢复周期，不能只恢复失效的引用。
- 草稿只在自己的宿主、仓库和保存位置中恢复；切换仓库不能带入上一仓库的图片。
- 「清空草稿」同时清空文字和草稿图片，提供一次整体撤销；可撤销期间保留所需图片。清空之后到达的异步结果不能恢复旧图片。
- 创建时将图片存入该任务材料目录，正文保存兼容现有 Markdown 的图片引用。离开创建窗口后仍能打开，不能依赖临时预览地址。
- 创建成功必须意味着正文及其所有本地图片已可靠保存。只保存部分内容时不能显示成功；重试应复用同一次创建身份，避免出现半张卡片或重复卡片。
- 清理仅作用于明确属于该草稿、且不再被引用或撤销记录需要的临时文件；不能删除用户选取的原图、已有任务图片或其他草稿资源。

## 范围与后续验收

本轮仅设计新建卡片详情的图片能力。插件、macOS 和 Windows 共享交互约定，宿主剪贴板／文件能力分别验收；现有创建后详情编辑作为兼容基线，不在本轮扩展成新编辑器。图片不自动变成卡片封面，不修改进展和待办的语义。

开发后的验收清单，当前均未执行：

- 单张截图、多图选择、拖入、纯文字和混合图文：插入位置正确，没有重复或丢失原文。
- 图片处理时继续打字或移动光标：图片顺序、文字和焦点保持正确。
- 移除／撤销、手动删除引用／撤销、处理中移除、清空草稿／撤销：正文和预览一致，迟到结果不会复活已删除内容。
- 关闭再打开：在宿主承诺的草稿周期内图文一同恢复；切换仓库不串草稿。
- 部分图片失败、磁盘写入失败、创建失败后重试：数据保留，不漏图、不重复卡片，也不提前生成正式任务。
- 创建后重新打开详情、重载插件、移动／导出任务：图片引用仍可用，导出与现有任务材料机制兼容。
- 短窗口、窄屏、深色主题：错误说明及图片列表不遮挡创建按钮；Tab 可操作所有按钮，Esc 先关闭图片预览。

建议先评审「Markdown 输入 + 缩略图预览」这一交互方向，再决定是否进入开发。
