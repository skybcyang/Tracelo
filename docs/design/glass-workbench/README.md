# 玻璃悬浮工作台 Mockup

2026-10-15 建立，2026-10-16 银灰材质与封面修订。独立、可点击的设计原型，用于确认页面形式及交互。使用合成任务和固定演示日期，所有编辑仅存在页面内存中，刷新会还原；不读取正式任务，不调用模型，不写 Obsidian 或桌面程序。

## 打开与试用

入口：[index.html](index.html)。在仓库根目录启动本地服务：

```sh
python3 -m http.server 4187 --bind 127.0.0.1 --directory docs/design/glass-workbench
```

浏览器打开 `http://127.0.0.1:4187/`。文件采用原生 ES Module，建议通过该本地地址打开。仅服务原型目录。

1. 组合选择“工作”和“重要不紧急”，结果取交集。
2. 在下方封面流滚动，浏览位置变化；点击卡片才切换上方任务。左右按钮和方向键也可浏览，封面流容器聚焦时 Enter 选择。
3. 点击“记录进展”输入，再切到其他任务；切回后仍保留未提交草稿。普通 Enter 换行，组合键提交。
4. “全屏总览”铺开当前结果；可切换分组／2×2 四象限，清除筛选显示全部。退出恢复展示台与横条位置。
5. 右上角可收起工作助手、切换深浅色、暂停背景光效。日历、活动记录、任务历史均可打开。
6. 右侧明确引用当前任务后，可体验本地固定规则生成的演示回答；这是交互占位，不是模型能力验证。翻卡不会改变引用。
7. 新建只填名称即可，默认未分组、不重要不紧急。创建和进展保存只是修改当前页的合成数据。

直接打开状态：`?state=dark`、`collapsed`、`overview`、`quadrants`、`editing`、`filtered`、`no-results`、`empty-task`、`long`、`history`、`activity`、`calendar`。`?motion=off` 暂停背景动效；系统减少动态效果另由媒体查询处理。

## 本轮设计取值

用户追加要求：加强透明毛玻璃与可见流光，先做大画幅，不处理手机形态。最终视觉以 1728×1080 桌面截图为准；初版窄窗口记录仅作为历史检查，不是本轮验收目标。

参考 [Apple Materials](https://developer.apple.com/design/human-interface-guidelines/materials) 区分阅读内容与导航材质：展示台用较厚毛玻璃，封面导航更通透。网页实现是 CSS 材质近似，不是系统原生 Liquid Glass，也未使用 SVG 位移折射。

最新增加 `materials.css`，使用 apple-design 的本地 token 基础，重新组织透明染色、背景模糊与饱和度、内侧高光、薄边和软阴影。10月16日移除贯穿画面的 SVG 光带，改为银灰基底、右后方冷色柔光、底部漫反射及边缘光斑；三个光层均支持暂停。移除封面流祖先的遮罩和展示台祖先的常驻透明动画，避免截断背景采样；卡片颜色因此真实随背景变化。

- 玻璃外层、柔和周边光效，正文区域保持较高遮罩；明暗共享布局。任务图标使用项目已安装的离线 Noto，许可在 [assets/noto-license.txt](assets/noto-license.txt)。未引入外部字体或 CDN 依赖。
- 展示台恢复左侧大进展、右侧待办与详情上下组合；输入在展示台展开，长内容自然增高。
- 封面采用左上30px小图标、两行18px主标题及底部12px属性，选中卡略大且保持正面，仅两端轻透视。封面不含进展正文。选中状态使用“当前任务”，与待办完成勾选区分。
- 右侧采用日历＋工作对话，可切活动和单任务历史；窄窗口成为按需展开面板。这是可试用的候选，尚不代表用户已确认右侧方案。
- 全屏暂解释为占满插件工作区，保留筛选；不是浏览器系统全屏。原位编辑和旧展示模式如何整合仍需后续产品设计。
- 封面导航移到牌组标题右侧，避免编辑时被挤到屏外；删去底部重复操作提示，助手空态说明压为一句。大画幅默认首屏容纳完整封面与导航；输入展开和长内容自然增高，可滚动阅读。本轮不继续手机形态设计。

## 现有架构的约束

结论：现有栈可以实现，无需为了视觉改版迁移 React 或更换存档协议。下列是代码检查结论，不是生产性能验收。

| 当前实现与来源 | 对正式实现的影响 |
| --- | --- |
| [package.json](../../../package.json)、[esbuild.config.mjs](../../../esbuild.config.mjs)：TypeScript、原生 DOM、esbuild，无 React／Tailwind | CSS 渐变、模糊、透视和少量 JS 足以实现本原型。React 卡牌库不能直接嵌入，应借鉴视觉并使用现有 DOM 体系实现 |
| [src/domain.ts](../../../src/domain.ts)：任务已有分组、重要／紧急、详情、待办和事件 | 联合筛选和展示台不要求迁移正式任务。新增的选中、浏览位置与全屏偏好属于界面状态 |
| [src/main.ts](../../../src/main.ts)：`viewMode` 在 group／quadrant 间切换，当前 `boardFilter` 主要筛分组 | 将“条件筛选”和“排列方式”拆开，独立维护 groupFilter／quadrantFilter，再复用分组与象限排序；不能把四象限筛选直接当视图模式 |
| [src/main.ts](../../../src/main.ts)：`render()` 会重建任务列，已有 composition 防护、焦点／滚动恢复 | 高频滚动不能触发整体 render。封面流只更新变换，选中变化更新展示台；进展编辑器要保持稳定节点，保护中文输入、草稿与焦点 |
| [src/conversation-panel.ts](../../../src/conversation-panel.ts)：已有独立稳定 DOM 容器与显式 `addReference()` | 可保留现有会话与引用语义，工作台选择不自动成为模型上下文；收起侧栏不销毁对话 |
| [src/task-card.ts](../../../src/task-card.ts)：卡片同时承载摘要、详情、待办与记录器 | 正式接入时拆出封面卡和展示台，复用业务动作与存档服务；不能只用 CSS 隐藏旧卡内容便宣称完成 |
| [desktop/README.md](../../../desktop/README.md)：macOS WebKit，Windows WebView2，共享表单与样式 | 新工作台样式必须限定作用域，避免影响快捷表单；若推广玻璃外观，再分别验证 WebKit 与 WebView2 |

玻璃只能折射／模糊网页自身层叠背景，不能据此承诺 Obsidian 窗口外的桌面穿透。大面积多层 `backdrop-filter` 和持续背景动效会消耗合成资源；正式版需限制模糊层数、离屏暂停、支持减少动态和不支持模糊时的实色回退。大量任务的封面流需要按实际数量测量，必要时仅绘制邻近卡片；本轮没有声称 100 卡性能通过。

正式接入建议先拆分视图状态与稳定编辑容器，再接展示台和联合筛选，最后接封面流及材质。保留既有保存回执、冲突校验、任务 ID、草稿隔离和 AI 提议确认机制。
