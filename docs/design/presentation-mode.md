# 等高卡片、展示模式与交互动效

2026-09-30 · 从 0.9.1 工作区实现，纳入 0.9.3。

## 依赖与边界

1. 偏好层：新增 `presentationMode`，新用户默认关闭。旧 `compactCards: true` 映射为关闭，显式 `false` 映射为开启；新字段优先。下次保存只保留新字段，不改任务 Markdown。
2. 阅读层：`presentationMode || expandedTaskId === task.id` 决定内容完整显示。关闭模式时保留正在编辑的卡片展开。
3. 编辑层：`expandedTaskId` 仍表示唯一编辑卡片。展示模式本身不激活编辑；展示模式结束编辑保留进展草稿、选中任务与历史阅读位置。紧凑模式收起沿用原有返回每日时间线的行为。
4. 布局层：紧凑卡片统一单行标题、标签与日期横排、进展标签与两行进展、底部操作；长标题与长分组名省略，展开后完整显示。完整卡片按内容自然增长。复用现有响应式列宽和稳定瀑布流列分配。
5. 动效层：重绘前读卡片尺寸／位置／进度，重绘后仅对差异过渡。业务状态先落实，动画可取消，减少动态效果时跳过。
6. 快捷操作层：继续使用共享表单和持久命令回执，不因动画提前确认成功或关闭窗口。

## 交互约定

- 「展示模式」在第二行工具栏右侧、「今天截止」之前，使用展开图标、文字与 `aria-pressed`。
- 模式保存成功才切换显示；失败保留原选择并显示错误。设置弹窗移除重复紧凑开关。
- 模式切换保留右侧时间线 DOM、选中日期、记录锚点；看板记录当前阅读卡片相对位置。原位替换非编辑卡片，当前编辑卡片及输入节点保持连接，保留 IME、未提交待办文字、保存锁与选择范围；偏好保存异步返回时不抢新焦点。
- 阅读中的待办可直接勾选；详情、链接、图片及文字选择不触发进入编辑。只有目标卡片出现进展表单。
- 展示模式下操作文案为「结束编辑」，提交成功退出编辑但继续完整阅读；失败保留输入与重试。
- 动效不引入新的排序逻辑或数据协议；不按卡片高度重新排序。
- 只给原视口可见卡片播放高度动画；阅读锚点上方卡片直接到最终高度，避免持续纠正滚动。瀑布流按任务身份查找最新卡片节点，窄屏重分列不会复活旧 DOM。

## 可点击原型

直接使用当前真实组件的隔离预览作为可点击原型，避免复制一套已过时的界面。运行 `node tests/helpers/ui-review-server.mjs` 后打开 `http://127.0.0.1:4179/?collection`。全部写入均在浏览器内存测试仓中，不接触正式任务。

验证顺序：等高卡片 → 展示模式 → 一张卡记录进展 → 结束编辑 → 关闭展示模式 → 恢复等高。另验证输入草稿后关闭模式，当前卡片仍展开，结束编辑才恢复等高。

## 验证分工

- 偏好迁移、模式按钮、持久化失败、时间线与阅读锚点：主视图集成回归。
- 等高、内容完整性、单卡编辑、主题／宽度／缩放：共享卡片回归。
- 动画中断、进度环、时间线新增、减少动态效果：动效回归。
- 提交中／待同步／成功／失败、模式切换与输入：快捷反馈回归。

本轮开发与验证不隐式发布，也不把自动浏览器验证记作 Obsidian 或 Windows 实机验收。
