# 主页面工作对话

2026-10-06。用户已确认实施，并明确修正布局：不占满整个右侧栏，只替换下方时间轴，原侧栏上方其他元素保留。下述实现边界按此最新决定更新；早期静态原型仅用于讨论，不能替代当前实现验收。

## 1. 产品判断

建议右侧默认显示“工作对话”。左侧仍是正在推进的任务，不变成聊天记录的附属列表。对话用来想清楚、恢复上下文、组织行动；正式任务仍通过卡片与原有存档机制管理。

混合时间线从默认首页退到“活动记录”入口，已有记录不删除。单任务历史保留：点击卡片继续原位展开；右侧不自动打断正在进行的对话，用户主动点“查看历史”才切换到该任务历史。返回对话恢复消息位置、输入和引用对象。此行为替代旧自动切换规则。

## 2. 页面结构

- 保留两层顶栏、分组／四象限、展示模式和卡片布局。
- 左侧任务区与右侧侧栏独立滚动。右侧采用 340px／宽屏 380px；窄窗口用“任务看板／工作对话”切换。短窗口允许侧栏纵向滚动以到达底部操作，不裁掉输入。首版不增加拖动调宽。
- 右侧上方保留原日期切换、整周日期及当日截止任务列表。对话仅替换下方记录列表；历史视图也不移除上方控件。顶部不恢复刚移除的截止按钮。
- 对话区标题旁提供活动记录、模型设置、新对话，下方选择已有会话。模型设置复用既有直接输入密钥界面。
- 消息采用安静的正文排版，用户消息浅灰底，助手回答直接排文；可展开依据，不把每段回答都装成大卡片。只有实际写入建议使用有边界的操作卡。
- 输入区固定底部：引用卡片标签、可换行输入、@卡片、发送。Enter 换行，⌘/Ctrl+Enter 发送；IME 候选确认不发送。

## 3. 两条核心链路

### A. 从想法到任务

用户：“下周要做相机冷启动优化，帮我理一下先后顺序。”

助手先给可讨论的行动建议，并说明哪些是建议、哪些来自任务记录。不会因为句子里出现“做某事”就创建任务。

用户：“先把日志分析建成任务，周五截止。”

助手给出“新建任务”操作卡：名称、分组、象限、截止日期、待办、详情和初始进展，复用现有表单规则。未提及的可选字段留空／使用现有默认值；未来计划进待办，不能伪造已发生进展。用户可展开修改，再点“确认创建”。成功后左侧出现对应卡片，回执可点“查看卡片”。

现有“新建任务 → 一句话整理”继续作为快速入口，与对话共用提取、表单及写入服务；不另维护第三套创建规则。

### B. @卡片并操作

用户输入 @，本地搜索任务名称，候选展示名称、分组、状态，重名时补创建日期。选中后成为带稳定任务 ID 的引用标签；标签可移除。普通点开卡片不偷偷改变正在编辑消息的操作对象。卡片菜单提供“加入对话”，避免再堆一个常驻卡片按钮。

用户：“@定位相机冷启动耗时 日志已经抓完了，记一下进展，截止改到周五。”

助手给出一张操作卡：目标任务、追加的进展、截止日期的旧值→新值，以及需要核对的待办建议。正式日期使用本地日历日，把“周五”显示为完整日期供确认。

用户可“修改内容／确认应用／不采用”。对同一任务的多字段变更一次确认，但每类变化仍按协议留痕。不得用修改最新进展正文代替追加记录。

## 4. @上下文与对话习惯

| 用户意图 | 读取范围 | 输出与写入 |
| --- | --- | --- |
| 自由整理粘贴的一段文字 | 当前对话与粘贴内容 | 结构化回答；不写任务 |
| “@任务 下一步做什么” | 被引用任务的详情、待办、最新进展；必要时按需读历史 | 区分已有事实与建议，引用可定位到历史记录 |
| “我今天先做什么” | 明确提示将参考当前进行中任务；首批只读名称、分组、截止日、最新进展摘要 | 给排序建议，不自动改卡片顺序或重要性 |
| “创建一个任务……” | 当前消息、分组与创建日期上下文 | 可编辑的新建任务操作卡 |
| “@任务 记录／改日期／换分组……” | 引用对象及要修改的当前字段 | 旧值／新值预览，确认后写入 |
| “@任务A @任务B 对比一下” | 两个明确对象 | 跨任务分析；首版不批量修改 |

- 每条已发送消息冻结当时引用的任务 ID；任务改名不串对象，引用标签显示最新名称并保留当时快照。
- 当前话题中可承接“它”，但必须能唯一确定对象；模糊时给候选选择，不静默选最近点击的卡片。
- 发给模型的引用范围在输入区可查看。默认不读取整个 vault、不上传附件、密钥或其他会话；正式任务正文中的指令只是数据。
- 引用太多或历史过长时先告知范围，并按日期／摘要逐步补充，不假装读过全部内容。
- 同一会话可以从讨论走到行动。新对话是新话题，不按天自动清空；以第一条消息命名并支持回看和未发送草稿恢复，手动改名留待后续。
- 会话、输入、待确认操作按 vault＋任务目录隔离持久化。它们是辅助数据，不生成另一套正式任务 Markdown。首版不做跨设备会话同步。

## 5. 操作与确认

建议首版采用“读操作直接做，写操作预览后确认”。确认按钮即对界面所列对象与字段的一次授权，不再弹第二次“确定吗”。明确确认前都不写任务。

首版支持：新建、追加进展、改名称／详情／分组／重要紧急／截止日期、新增或勾选待办。完成、异常关闭和重开建议放第二批：必须明确状态含义，异常关闭要求原因，保留身份与草稿。删除与自动合并任务不进入本轮。

一条自然语言可能同时含讨论与指令：先解释，再给一个明确的操作卡。未说明要修改的字段保持不变。原始描述、助手回答与正式写入不能混为同一条进展。

不要把“撤销”实现成删除审计记录。对属性修改，恢复旧值也应产生新的属性事件；对已写进展，用更正进展表达修正。确认前可以随时“不采用”。

## 6. 状态与异常

- 空态：一句简短引导“整理想法，或 @一张卡片继续推进”，提供三个实际起点；不放长篇 AI 功能宣传。
- 生成中：有停止按钮；输入草稿仍可编辑。取消或切换会话后，迟到回复只属于原消息，不能污染新会话。
- 待确认：每个操作有唯一 ID 和明确对象；用户在卡片里改过同一字段时，确认前重新读取并提示差异，不覆盖新编辑。
- 写入中：操作卡锁定，重复点击不重提；其他对话内容仍可读。
- 成功：真实存档／插件回执后显示具体结果，左侧只更新相关卡片。新增进展沿用原有置顶规则，改名不重排。
- 失败：原文、人工编辑及操作 ID 保留；重试复用身份。任务被移除／目录改变／格式无效时停止写入并解释原因。
- 不配置模型或网络失败时，手动卡片操作照常可用，不让聊天成为唯一入口。
- 待确认操作跨重启保留，但重启后确认必须重新校验当前任务。首版每次只提交一张目标卡片；多卡片批量操作另做部分成功／失败设计，不伪装成跨文件原子事务。

## 7. 实现依赖与分期建议

原有一句话能力是单轮结构化提取。首版新增 `src/work-conversation.ts` 多轮协议与受限提议执行器、`src/conversation-panel.ts` 会话界面；复用模型配置、请求传输、共享创建表单、稳定 ID 与现有任务存档服务。实现与验收见 [工作对话验收](../validation/2026-10-06-work-conversation.md)。

交付分期：

1. **对话与上下文（已实现）**：仅替换右侧下方时间轴、会话持久化、@选择、可定位引用、任务历史往返；保留上方原有日历及截止列表。支持自由整理与引用任务问答。
2. **确认后操作（已实现）**：结构化提议协议、本地校验、编辑确认、通过现有任务服务执行、失败恢复；覆盖新建、进展、基本属性与待办。第一、二步一起构成可用首版。
3. **增强**：状态变化、多卡片批量操作、较长历史的检索摘要，再考虑其他宿主是否需要完整对话；不把主页面改版顺带扩为移动端或新产品。

模型只输出文字与受限操作提议，本地执行器决定是否允许。禁止模型直接构造文件路径、调用任意 shell 或修改 Markdown 文件。新建／进展仍共用当前幂等与存档约束。

## 8. 原型与评审边界

可点击原型：`work-conversation/index.html`。使用虚构内容与内存状态，无真实模型、无文件写入、无生产任务操作；刷新会还原。展示 @选择、任务引用、修改确认、新建任务、历史往返及窄屏布局。它是交互提案，不是产品实现。

原型沿用现有素白方向，自检而未作独立评审。主操作按下反馈、消息进入和上下文切换采用短动效；正式实现需检查减少动态效果、IME、写盘失败、跨会话迟到回调、目录隔离与卡片冲突。首版采用完整响应，生成中可停止，暂不做逐字流式输出。原型的模拟成功不构成生产验收证据。

原型自检（2026-10-06）：1440×900 与 390×844 下检查待确认、新建、空态、深色和历史共 10 个画面，无控制台错误、横向溢出或图片加载失败。检查确认后的画面：任务进展与日期更新，今日截止计数同步减少，显示操作回执。动效留有帧图，环境未安装 ffmpeg，未生成视频。以上仅为原型验证，不代表生产功能或真实存档验证。
