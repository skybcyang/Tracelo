# 快捷入口：真实状态与短反馈

2026-09-30。覆盖插件共享新建表单、插件内快捷进展、macOS WKWebView 和 Windows WebView2 共用页面。没有修改任务存档、命令或 receipt 协议。

## 依赖与盘点

- `new-task-form.ts` 已统一新建表单、IME、草稿、附件及 saving 防重入；此前成功状态由宿主立即关闭窗口，表单仅显示“创建中”。
- `desktop-progress.ts` 已统一插件/桌面进展编辑与持久操作。`queued` 并不等于成功，只有实际写入完成的 `applied` 可以清稿并结束会话。
- 原生宿主负责实际落盘、持久草稿及焦点恢复，共享页面负责短确认/退出反馈。桌面状态明确设置 `presentationMode=false`，不受看板展示模式影响。
- 表单的 `confirmSaved()` 仅由宿主在实际创建完成后调用；桌面仍以原有 `draft:null` 成功状态作为写入完成信号。

## 采用的反馈

| 场景 | 反馈 | 状态约束 |
| --- | --- | --- |
| 窗口内容出现、模式/任务切换 | 160 ms 透明度淡入 | 不整体平移表单，防止固定提交栏越出视口 |
| 可选字段、待办行、进展附加项展开 | 相同 160 ms 淡入 | 同步展开并立即交还输入焦点，不等待动画 |
| 新建提交 | “创建中…”及 live status | 锁定提交与正文，失败原地显示错误且保留完整草稿 |
| 已暂存的进展 | 独立 `queued` 状态和“等待写入”文本 | 不清稿、不播放成功、不自动退出；重开附着于原命令 |
| 进展、待办写入完成 | `success` 文本；已确认的待办行淡入 | 只在 `applied` receipt 后确认 |
| 创建/进展最终成功 | 280 ms 短确认，然后结束会话 | 确认期间禁止重复提交；新打开的会话不被旧延迟关闭 |
| 页面关闭、取消、成功退出 | 100 ms 淡出 | 退出期间冻结输入；原生草稿保存失败可恢复操作 |

`prefers-reduced-motion: reduce` 下不启动这些动画，也不等待成功确认时间；文本、禁用状态和屏幕阅读器反馈仍保留。动画不驱动持久化，也不决定是否写入成功。

原生系统快捷键或系统关闭按钮触发的窗口隐藏继续使用现有宿主关闭与焦点恢复机制，不额外插入系统级缩放/位置移动动画；共享页面的关闭按钮、Esc 和成功退出有统一淡出。窗口边框形态、跨屏定位及操作系统合成动画保持系统行为。

## 失败与输入保护

新建和进展均保留失败草稿；重试复用原请求/命令身份。提交中的改名/编辑等弹窗禁用取消与 Escape，失败后恢复原输入。IME composition 期间不提交或关闭。新建表单使用提交代次，快捷窗口使用会话代次，防止旧异步结果覆盖新打开的草稿或关闭新会话。

进展仍共用卡片 composer；收到 applied 时先锁住成功确认阶段的 composer，防止旧文字尚在画面上时被再次提交。普通状态刷新不重播任务切换入场。
