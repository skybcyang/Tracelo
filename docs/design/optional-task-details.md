# 可选待办清单与截止日期 · UI/UX 提案

日期：2026-09-26。状态：设计评审稿，已接入插件代码；原型仍是独立的交互参考。

交互原型：[optional-task-details.html](optional-task-details.html)。直接用浏览器打开，无外部依赖。示例“今天”固定为 2026-09-26；仅使用页面内存，刷新会恢复示例，不读写实际任务。

## 设计边界

每个任务可以选择：两者都没有、只有待办、只有截止日期、两者都有。默认两者都没有，不显示“未设置”或“0/0”占位，不要求用户先启用功能开关。任务级截止日期精确到天，清单只有一层。此次不涉及子项日期、通知、周期任务或拖动排序。

## 视觉与布局

延续 Precision Chrome 设计基线：冷灰工作区 `#edf0f4`、浅色面板 `#fbfcfe`、正文 `#172033`、辅助文字 `#5d6b7f`、蓝色操作 `#245be7`。原型为临近截止使用琥珀 `#96570e`；插件当前对已逾期任务使用红色与明确文字提示。

系统中文字体；页面标题 19–20px，卡牌标题 15px，内容 12–14px，辅助信息 11–12px。桌面中等密度，卡牌等宽，不用百分比进度条暗示工作量。

- 收起采用三段结构：顶部标题／菜单 → 中间最新进展 → 底部信息区。底部上行只放已有的待办计数／截止日期，下行左侧放分组和象限标签、右侧放更新时间。
- 使用紧凑密度：四边内距 12px；标题与进展、底部信息行之间为 4px；区块间距为 8px。字体大小保持不变，收起卡牌的底部属性位置一致；未添加功能不显示空标签。桌面待办行高 32px，窄屏保留 44px 操作行高。
- 展开：摘要 → 清单（存在才出现）→ 可选添加入口 → 进展输入。新增控件不能嵌入整卡按钮，避免勾选误触收起。
- 标题按钮只包含标题，最新进展为独立正文；显式覆盖 Obsidian 默认按钮的定高、居中、灰底和不换行规则。展开后显示 28px 短侧标，收起即移除；展开不自动聚焦进展输入框。
- 已有清单展示完成数、行分隔与常驻新增输入框；无清单时仅显示“添加待办”。图标与文字分开渲染，避免宿主图标 API 清除文字。
- 对齐单位是一张完整的基础卡牌，基础高度 148px、间距 12px。普通内容统一占一格；卡牌等宽，列边缘与行边缘对齐。
- 高度根据内容占用最少整数格：`格数 = ceil((内容自然高度 + 间距) / (基础卡高 + 间距))`，`卡高 = 格数 × 基础卡高 + (格数 − 1) × 间距`。两格 308px、三格 468px，只有内容需要时才扩到四格或更多；不强制四格。展开卡牌底边与旁边对应数量的基础卡牌底边对齐。
- 长标题或长进展导致收起态超过一格时，也按相同规则占用更多整格，不能为保持一格而裁切文字。整格内允许为边缘对齐保留空白。
- 收起时，完整显示最新进展并自然换行；展开后，清单随项数及文字长度增长。添加、删除、改文案、设置／清除日期以及窗口缩放后重新测量高度。清单不再设置固定内部滚动高度，由任务栏统一滚动。
- 插件按容器宽度自适应：卡牌最小宽度 260px 并自动增列；容器 ≤900px 时右侧时间线下移，≤600px 时卡牌单列。独立原型使用自己的演示断点。
- 支持独立浅色／深色预览、键盘焦点、减少动态效果。原型无持续动画。

## 入口与操作

| 入口 | 行为 | 取消／退出 |
| --- | --- | --- |
| 新建任务 | 原有必填项保留；“添加待办”“设置截止日期”按需展开 | 取消不产生任务 |
| 点击任务标题 | 展开卡牌并切换右侧任务历史 | 再次点击收起；草稿保留 |
| 点击待办计数 | 展开并定位首条待办 | 不自动新增空项 |
| 无清单卡牌的“添加待办” | 显示输入，回车添加；已有清单常驻新增输入框，可连续录入 | 首项未提交前可取消／Escape；空输入不产生清单 |
| 勾选／取消勾选 | 原位更新计数并追加历史 | 再次勾选可恢复；不重排、不置顶 |
| 编辑待办 | 小型编辑对话框，回车保存 | Escape／取消保留旧文本 |
| 删除待办 | 删除当前项并追加历史 | 提示提供撤销，恢复原位置和完成状态 |
| 点击日期标签 | 原生日期输入，提供快捷日期和清除 | Escape／取消不保存 |
| 查看截止日 | 切换到该日期的每日时间线 | 返回任务可继续操作；左侧卡牌不变 |

清单全选不会自动完成主任务。结束时仍有未完成项，明确提示剩余数量并提供“返回处理／仍然完成”；不自动勾选。结束后清单只读，允许重开。截止日期作为属性仍可调整。

新建清单允许删掉全部待办，随后恢复“添加待办”入口。清除截止日期后恢复“设置截止日期”入口。文字统一使用“待办”“截止日期”“记录进展”，不向用户展示数据模型词汇。

## 时间线语义

每日时间线可选择未来日期，且不会自动改变左侧任务集合。顶部单独显示“当日截止”，无截止任务时整个区域隐藏。真实历史按时间正序放在下方滚动区，固定截止区不因滚动而消失。

截止区不参与历史区的纵向压缩；多个截止任务超出可用高度时独立滚动。截止条目和历史任务链接显式覆盖宿主按钮灰底，避免信息层级与原型不一致。

单任务时间线顶部显示当前截止摘要与“查看截止日”；无截止日期时整个摘要隐藏。未来截止安排没有虚构的发生时间，不混入已发生事件。

修改日期的当天追加“截止日期：旧日期 → 新日期”，当前截止标记移动到新日期；清除后标记消失，变更历史保留。这是当前计划的投影，不是“当时计划”的历史重建。

已完成任务仍可在其截止日看到完成状态，不标逾期；重开后重新判断。日期按当地日历日判断，到次日才算逾期；日期跨时区不平移。原型固定示例日期；插件每分钟检查是否跨日，并在日期变化时刷新今天的显示。

待办完成／取消完成清晰展示，增删改作为次级记录；不覆盖卡牌最新进展。正式进展提交仍保留现有“收起并置顶”的行为。

## 状态与无障碍

- 空值：不出现日期／清单占位；无搜索结果给出明确说明。
- 取消：日期与待办编辑不影响旧值；清单勾选可直接反转，删除有撤销。
- 长内容：标题、最新进展和待办文字完整换行，禁止纵向压缩或隐藏半行；卡牌按内容长高并重新对齐，任务栏提供滚动。
- 错误（正式实现要求）：写入失败保留输入、恢复控件，显示“未能保存，请重试”；不能把本地显示当成持久化成功。原型不模拟文件错误。
- 交互：使用原生按钮、日期输入、复选框和对话框；图标有名称，弹窗支持 Escape、焦点约束及返回。
- 触屏：单列、独立点击控件，正式实现以 44px 点击区域验证；不依赖悬停或右键。

## 评审路径

1. 初始画面比较四种组合；纯进展卡无多余占位。
2. 在支付模块中勾选、修改、删除、撤销待办，检查计数和历史联动。
3. 将支付模块改期到今天，进入每日时间线；再清除日期，确认截止安排移除且历史保留。
4. 新建任务，直接不加两项内容；另建一张按需添加两项的任务。
5. 完成一个仍有待办的任务，再重开；检查待办完成状态未被代改。
6. 切换深色／窄屏，检查信息层级、滚动、弹窗与键盘操作。

## 原型与正式实现的区别

原型验证视觉与交互方向，不代表功能验收，也不读写真实文件。插件实现使用现有 Markdown 存档与备份流程，旧 v1 存档保持兼容；目前不提供系统通知，日期状态会随跨日检查及界面重新渲染更新。

## 回归验证

`npm run check` 包含真实插件渲染代码的浏览器测试：加载宿主按钮／输入框样式与图标替换行为，覆盖四种可选属性组合、展开／收起、清单增删改与撤销、日期修改、草稿保留及浅色／深色不同宽度。另以布局测试验证 148px 基础网格、内容完整显示、最少占格、缩放和独立滚动。浏览器宿主适配层不能替代真实 Obsidian 的最终视觉检查。
