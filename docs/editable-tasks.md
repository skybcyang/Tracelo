# 可编辑任务存档（0.9.5 起）

任务仍位于 `工作记录/任务/`，不按分组或象限拆分文件夹。没有附件时为单个 Markdown；有附件时为同名文件夹中的同名 Markdown，图片等材料放在该文件夹内。分组定义保存在 `_groups.md`，视图偏好和未提交草稿在插件的 `data.json`。

双击卡片的正文或空白处，会在 Obsidian 新标签页打开对应文件，保留看板。右键菜单的“打开任务文件”提供相同入口；键盘可用 Shift+F10 打开菜单。标题、按钮、链接、图片、复选框和输入框保留原操作。单击正文约 300 毫秒后展开；点击标题可立即展开。

## 编辑方式

文件头是 YAML 属性：`tracelo: 2` 标记格式，`id` 是固定身份。`status` 使用 `active`、`completed` 或 `closed`；`important`、`urgent` 使用 `true` / `false`；`dueDate` 使用 `YYYY-MM-DD`，留空可清除。修改 `groupName` 可切换到已经存在的分组，写“未分组”可取消分组。新分组先在插件内建立。自定义 YAML 属性（如 `tags`）会保留。

任务名称在 `# 标题` 中；`## 详情`、`## 待办`、`## 时间线` 是三个固定分区，请保留顺序。详情支持 Markdown，内部小标题推荐使用三级或更低级标题；不要添加与固定分区同名的二级标题。待办使用普通 `- [ ] 内容` 和 `- [x] 内容`，可直接新增行、修改文字或勾选。

时间线以三级标题记录时间和类型，例如：

```markdown
### 2026-10-06T10:30:00+08:00 · 进展

完成第一轮验证。

- 修复了两个问题
- 下一步检查边界情况
```

现有待办和事件附近的隐藏注释保存固定 ID、事件类型及历史时区／属性快照，用于保留历史和防止快捷操作重复执行。它们不再包含一整份重复的任务正文；不要手动修改这些身份注释。详情变更事件仍可能保存变更前后内容，这是历史记录。新增待办或进展可不写注释，插件会生成身份；之后由插件保存时写回。历史记录可以通过文件修改，不属于不可篡改的审计数据。

## 刷新与保护

Obsidian 保存文件后，插件等待约 250 毫秒合并连续修改，再更新卡片、分组、象限和时间线。刷新保留未提交输入及光标。文件编辑不会额外伪造一条插件操作事件。

YAML 或正文未写完整时，原文件保留，卡片继续显示最近有效版本并暂停该任务写入；修正保存后自动恢复。重载时若有有效备份也只用它显示，不覆盖正在编辑的原文件。插件保存前检查文件是否发生变化，在 Obsidian 内通过 `vault.process` 比较并更新，冲突会提示重试。

重命名单个无附件任务文件后，固定 ID 继续关联卡片；后续保存保留用户文件名。带附件任务仍要求同名文件夹／同名 Markdown，建议用插件的改名功能一起移动。删除文件会移除卡片，不再自动恢复文件，已有备份保留。

## 迁移、备份与兼容

插件读取旧 v1 文件，并在迁移前把原始文件逐字节保存在 `.obsidian/plugins/work-timeline/backups/format-v1/<任务ID>.md`。任务 ID、历史 ID、附件和草稿保留。旧存档或桌面工具新建的 v1 文件会转为 v2。

每日备份保留最近七天；格式迁移备份与 `backups/editor/<任务ID>/` 中的编辑前快照不参与七天清理。旧版插件不理解 v2，因此不要在没有恢复旧文件备份的情况下降级。迁移后新增的记录不包含在旧备份里。

配套桌面工具的源码已支持读取 v1/v2；原生创建仍以 v1 原子发布，再由插件接入并迁移。已安装的旧版独立桌面应用需升级后才能列出 v2 任务；只更新 Obsidian 插件不会更新独立应用。
