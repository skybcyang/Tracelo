# 0.9.1 发布验收

本次包含四主题与辅助界面一致性修正、截止日历、图文创建／快捷进展、Noto 图标、导航与瀑布流整合，以及移除虚线新建占位框。插件、npm、锁文件、版本映射与 macOS／Windows 源配置统一为 0.9.1。

## 本地验证

- `DOTNET_PATH=/tmp/tracelo-dotnet/dotnet PLAYWRIGHT_CHANNEL=chrome npm run check` 退出码 0：17 个测试文件、95 项单元／跨语言测试全部通过，无跳过；类型检查、生产构建及全部图标、布局、主题、图片、日历与快捷进展浏览器套件通过。
- 新增辅助主题回归共 77 项；卡片交互 87 项，布局和瀑布流各 27 项，搜索导航 13 项。
- 修正日历测试的初始化时序：在创建样本前安装模拟时钟，避免真实日期超过固定测试日期后出现历史倒序；未修改产品的历史校验逻辑。
- `bash desktop/package-macos.sh` 通过，0.9.1 通用应用包含 arm64／x86_64；签名核验、原生 WebKit 表单与原子发布／重试冒烟通过。
- `git diff --check` 与本轮文档相对链接检查通过。

## 发布流程

首轮远端插件与 macOS job 通过，Windows 原生窗口未能完成加载，已取消该次发布。排查发现共享表单 bundle 约 25 MB，超出 WebView2 `NavigateToString` 的 2 MB 上限。修复为 WebResourceRequested 从内存响应唯一的本地页面 URL，其他请求仍拒绝，消息来源同样严格匹配；不启动网络服务，也不将任务内容写入网页临时文件。官方限制见 [Microsoft 文档](https://learn.microsoft.com/dotnet/api/microsoft.web.webview2.core.corewebview2.navigatetostring)。

同时为 Windows smoke test 增加 120 秒进程上限、5 秒故障诊断上限与即时错误日志；CI 仅上传截图和日志，避免读取 WebView2 仍锁定的配置文件。修复后本机 Windows 交叉编译零错误／零警告，17 项核心测试及 3 项协议／版本检查通过。[修复分支 CI](https://github.com/skybcyang/Tracelo/actions/runs/36610370079)的插件完整回归、macOS 核心与 Windows 原生窗口检查全部通过。首轮标签尚未生成 Release，正式发布标签随后纳入此修复。

最终标签 `0.9.1` 指向 `444b3f046dd15acc74ef3d6a60d74ec4da7fc46c`。[正式 Release 工作流](https://github.com/skybcyang/Tracelo/actions/runs/36611366848)的 plugin、macos、windows、publish 四个 job 全部成功；[同提交主线 CI](https://github.com/skybcyang/Tracelo/actions/runs/36611367772)也全部通过。

[Tracelo 0.9.1](https://github.com/skybcyang/Tracelo/releases/tag/0.9.1) 于 2026-09-30 02:24:45（Asia/Shanghai）正式发布，非草稿、非预发布，共七个附件：三个安装 ZIP、三个插件独立文件及 `SHA256SUMS.txt`。

六个安装附件的 GitHub 上传摘要与 `SHA256SUMS.txt` 全部一致。已下载插件 ZIP、macOS ZIP、manifest、styles 和校验文件并计算 SHA-256；插件 ZIP 内三个文件与独立附件摘要逐项一致，插件及 macOS 包版本均为 0.9.1。Windows ZIP 为 71,765,959 字节，核对了 GitHub 上传摘要，未完整重下载；该包由 Windows runner 完成原生窗口冒烟后上传。

## 发布复盘

下次可直接使用[发布操作手册](../releasing.md)。这次主要耗时在网络重传和过早打标签；解决方式与复用规则如下。

| 坑 | 本次原因与处理 | 下次提前做什么 |
| --- | --- | --- |
| GitHub API 与 Git 推送表现不一致 | CLI 未继承系统代理；API 加代理可用，HTTPS 大包仍多次超时，最终 SSH 经本机 HTTP 代理连接 443 成功 | 小请求验证 API、SSH 认证，再上传；失败先查远端 SHA，不重复盲传约 24 MB 的 pack |
| 打标签后才发现 Windows 页面无法加载 | 约 25 MB 的共享页面超过 `NavigateToString` 2 MB 上限，改为内存响应页面资源 | 先在候选分支运行三平台 Release 构建，Windows 原生窗口通过后才打标签 |
| 原生故障拖成 CI 长时间无输出 | 错误诊断截图等待未完成加载的隐藏窗口；进程没有等待上限 | 已增加进程 120 秒、诊断 5 秒上限，并先写错误日志 |
| 收集证据又报 `EBUSY` | 整目录上传读到了 WebView2 锁定的 profile | CI 已改为仅上传 PNG 和 TXT，保留原始故障信息 |
| 版本已改但契约测试仍失败 | 固定断言还写着 0.9.0，README 下载名也要同步 | 将版本契约测试放在完整浏览器回归之前，逐项检查版本与下载说明 |
| 日历测试跨天后历史倒序 | 按真实时间创建数据后，才将时钟回拨到固定测试日期 | 已改为创建样本前安装测试时钟，不放松产品历史校验 |
| 上传期间混入后续开发的风险 | 原工作区继续有卡片、展示模式和动效改动 | 独立发布工作区、冻结 SHA、明确挑选文件；本次保留后续改动，未纳入 0.9.1 |
| 重复检查与大包下载拖慢收尾 | 本地、分支 CI、标签 CI 有重复工作；Windows ZIP 约 71.8 MB | 代码稳定后做一次完整本地检查，专项修复按范围验证；记录 CI SHA，区分上传摘要核对与实际下载验证 |

第一次标签尚未生成公开 Release 时才进行了修正；正式版本指向上文的 `444b3f0`。下次用候选分支预检避免这一例外，已经公开的标签不移动。

上述 CI 防护已随 0.9.1 发布；手册记录的本地 Windows 验证脚本差异、版本自动化和产物复用仍是后续改进项，本次复盘没有修改流水线。

Windows 原生窗口由 Windows runner 验证；完整真实输入法、多屏、剪贴板、焦点恢复及第三方主题矩阵仍不等同于已全部验收。
