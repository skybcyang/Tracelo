## 本轮发现与修复边界

1. **任务已保存但界面状态失败会重复创建（P1，已修复）。** 初查 `addTask` 在写入任务文件后继续等待 `persistState`，错误上抛至创建弹窗，用户重试得到第二个 ID。隔离复现计数为首次报错后 1 份、重试后 2 份。现在区分已成功的任务存档与附加排序偏好失败，提示“任务已创建……无需重复创建”并正常关闭弹窗；专项回归通过。
2. **仅改变分组／象限的草稿被丢弃（P2，已修复）。** 旧 `NewTaskModal.saveDraft` 只检查文本、待办、日期和进展，忽略属性选择。共用表单现在追踪实际修改并保留属性草稿；单纯打开／取消不会把入口默认值误存成草稿。专项回归通过。
3. **首次待办输入的 IME Esc 误取消（P2，已修复）。** 原 `renderTodoDetails` 的 Escape 分支没有 `isComposing` 防护。本轮增加组合输入状态跟踪，候选阶段 Esc 保留输入，Enter 不提交，组合结束后正常提交。
4. **多个直接操作失败没有可见反馈（P2，已修复）。** 菜单分组／象限／重新打开、卡片和空白区域拖放、分组排序、看板切换／展示／缩放此前抛出未处理 Promise，用户只看到操作无效。本轮统一通过 `runWithNotice` 捕获并呈现原始错误，成功路径继续原有渲染和焦点逻辑。

初查源码行号（共用表单抽取前）：`src/main.ts:1727` 新建写入、`:287` 草稿过滤、`:1234` 待办 Escape、`:1317` 菜单分组、`:1323` 象限、`:1339` 重新打开、`:1043` 卡片拖放、`:878` 区域拖放、`:554` 分组排序、`:776` 视图切换。抽取共用表单后行号会变化，以方法名为准。
