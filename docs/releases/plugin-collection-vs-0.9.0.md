## 采用的设计

以 [六款插件尺度 mockup](../design/plugin-collection/README.md) 的 A 矿物绿为默认界面，D 石墨紫、E 冰川蓝、F 暖白朱砂作为可切换主题。四款共用卡片、时间线、快捷创建和快捷进展结构，各有浅色／深色，也可跟随宿主。B 宝马工业、C 霓虹不加入本次正式主题；所有旧设计文件保留。

配色直接对应存档 `themes.css` 的画布、卡面、输入表面、文字、边框、强调色、状态色和分组色；圆角分别为 A 10px、D 8px、E 10px、F 7px。石墨紫使用较硬的中性表面；朱砂保留圆形品牌标记与分组标题下划线。

## 哪些是此前未发布工作，哪些是本次新增

此前工作区已有截止日历、桌面快捷进展及持久队列、创建前图片、原子发布、按仓库隔离的桌面草稿等功能。它们相对发布标签 0.9.0 是新增，但不能全部算作本次换 UI 才开发的功能；背景见 [此前未发布记录](unreleased-2026-09-29.md)。

本次新增或重做的是 A/D/E/F 主题、配色同步、项目列布局、常驻时间线与周日期条、倒序阅读、直接可见待办、紧凑设置、插件／桌面快捷表单结构、表单内任务选择器，以及快捷进展的真实图片保存链路。

## 保留的功能与数据约定

- 任务、详情、待办、分组、重要／紧急、截止日、任务图标、改名、完成／关闭／重新打开仍可操作；低频操作保留在更多／右键菜单中。
- 搜索仍可命中详情、历史进展和日期并定位原记录。缩放仍为 60%–120%；修改显示偏好不改任务内容或历史时间。
- 任务 Markdown 继续使用 `work-timeline-task:v1`，现有任务、材料、备份及导入导出保留。新增界面偏好写入插件状态；任务目录内 `.tracelo-ui.json` 是桌面工具读取的显示偏好，不是任务正文。
- 桌面创建可在 Obsidian 关闭时直接生成新任务。桌面修改已有任务先入持久队列，插件正式应用后才显示成功并清空草稿；未运行时为“已暂存”，不伪装已完成写入。
- 快捷进展图片先校验并写入任务目录，再提交事件；重试使用稳定请求 ID、文件名与内容摘要，丢失回执不重复追加进展。事件元数据不塞入整段图片 Base64。
- 插件快捷进展草稿按任务保存；插件新建草稿仍以当前仓库会话为最低保留范围。桌面草稿继续持久化且按仓库／目录隔离。

## 与静态 mockup 的接入差异

主看板、主题、常驻时间线与两种快捷工具按选定稿实现，但不将示意内容伪装成真实功能。以下差异明确保留：

1. 不在 Obsidian 内复制 mockup 顶部的假宿主标题条，也不复制网页外部的快捷键说明背景；实际窗口由 Obsidian、AppKit、WebView2 承载。
2. 日期、任务数、进展时间和事件数量来自真实数据；历史包含属性变化，不只显示 mockup 的四条示例进展。详情支持真实 Markdown／附件，卡高随内容变化。
3. “任务完成后自动归档”在原型中只是视觉开关。正式版沿用完成后移入“已结束”的既有策略，并用说明文字解释，不提供无效开关。“已结束”打开列表弹窗，可重新打开任务；点击标题还能回到完整任务卡片查看详情、附件及原有操作。
4. 真实文件选择器、日历输入、右键菜单、系统快捷键设置与成功通知遵循宿主。快捷键在桌面工具中配置；没有在插件视图冒用 Obsidian 的全局 ⌘K。
5. 图片显示实际大小限制和处理错误，保存失败保留草稿、提供重试／撤销；这些生产状态比静态稿多。提交成功后使用现有宿主关闭／反馈流程，不停留在原型示例成功页。

因此这不是声称所有宿主和所有内容逐像素相同的网页复刻；上面的接入差异可据此继续评审。
